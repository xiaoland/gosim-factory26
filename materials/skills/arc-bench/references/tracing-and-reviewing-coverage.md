# 需求覆盖结论的依据

追溯的价值，是使当前候选、原承诺、仍欠义务和有效证据之间的关系可以恢复。节点身份与原文位置保存来源，项目定义保存共同解释，任务材料连接工作与结果。映射的用途是支持判断；索引规模或全量状态表自身没有说明覆盖是否成立。

## 四种关系解释不同事实

| 关系 | 成立依据与用途 | 与其它事实的区别 |
| --- | --- | --- |
| 来源与层级 | 原节点、适用父层与跨枝正文界定承诺。 | 树形既不决定每叶分工，也不使子项自动取得父正文。 |
| 工作依赖 | 消费者所需成果及动作前提决定哪些工作可推进。 | 字段关联与实际时序可能不同。 |
| 责任归属 | 当前范围与实际接手说明谁推进、谁汇总剩余结果。 | 消息送达或对象关联未必已经完整承接。 |
| 证据支持 | 判据、候选、条件与观察共同界定支持范围。 | 映射齐全、检查全绿与完整覆盖具有不同成立条件。 |

共享接口可以兑现多个节点，同一节点也可能需要几项实现和观察。关系是否完整取决于实际约束，不取决于一一对应。局部要求可以直接体现在实现与判据中，共同合同的意义则是保存真实共享约束。

工作边界形成或改变后，沿原树回查：父层规则是否仍有适用消费者，每项局部能力是否包含成功、失败与状态保持条件，跨枝旅程是否有人汇总，排除或未核实的义务是否仍有责任入口。种子、接口和导航等共同成果已有人负责，不证明每项业务已经采用它们。原树没有责任空洞、相关材料可由负责人取得、局部与整体完成依据明确，才支持分工已承接完整范围；工作项数量或全量场景映射不能代替这项判断。

## 接手改变责任，没有缩减承诺

前序延期或排除的结果仍由原文及适用父层、跨枝条件界定。当前 PR 的叶子范围如果只含其中一部分，原承诺的其余结果仍欠。完整义务进入现有工作或者由整体负责人另作安排，才有责任落点；随后取得适用结果，才有兑现依据。[交接与变化](../../braid-collaboration/references/handoffs-and-changes.md)解释两者为什么可以在不同时间成立。

局部观察可以正确且值得接受，同时没有涵盖另一个入口或状态。来源引用使要求可定位，并不证明结果；缺少测试文件也不等于缺少可靠观察。具体依据的选择与解释由 [svc-verification](../../svc-verification/SKILL.md) 展开。

## 新解释与检查修正各有依据

新增用户可见约定的地位取决于原文、适用条件和授权。派生合同可以准确保存一个错误解释，其成功交接并没有解除原约束。明确冲突意味着约定及实现需纠正，真正歧义与范围改变涉及相应决定权；没有共享影响的普通实现选择无需因此提升为产品决定。

某个检查使用了不合适的输入，可以支持修正判据，却没有独自支持候选的额外行为。检查正确性与产品正确性由不同事实决定。相关分歧见 [接受与关闭](../../braid-collaboration/references/accepting-and-closing.md)。

## 声明与变化决定结果适用性

本次 PR 声明与前序开放义务共同界定需要支撑的原结果。用户入口实际进入了接口所需条件，并取得适用可见结果，才建立局部能力与用户承诺的连接；原文中的连续操作和失败后状态也属于结果。矩阵、文案与既有 spec 只涵盖其中已表达和观察的部分，逐节点关联或重跑全绿不能扩大它们的范围。

父层或跨枝规则改变，影响由其实际作用的对象与路径决定；新增消费者或派生状态即使格式不变，也可能改变读写、刷新与失效关系。祖先状态、显式依赖表及节点完成标记各自只保存部分事实。

修改后的旧证据是否适用，取决于相关行为、共享代码、数据、环境或判据的变化。未受影响且条件适用的结果仍可复用，缺少观察的承诺仍欠；固定层次全量重跑与提交号本身没有替代这个判断。有区分力的观察能够补足具体未知，重复同一遗漏判据则未必增加依据。

当前候选的已支持范围、剩余结果、原始证据与实际责任入口，使局部合并、继续工作或整体结束分别有可检验的理由。[共享设置例子](../../braid-collaboration/references/worked-example.md)展示有效局部成果先合并与整体尚未完成可以同时成立。材料足以支持当前决定、没有新的变化时，追溯维护可以停止，而未兑现义务仍按其责任继续存在。
