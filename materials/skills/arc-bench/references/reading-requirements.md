# 原始材料如何界定完整承诺

根 Issue 指定的允许需求是产品依据。Markdown 与 YAML 可能表达同一内容，也可能各有独有约束；格式方便与语义权威是不同性质。文件缺失、损坏或冲突使某项解释缺少依据，具体来源与原错误让这个未知可定位，独立可理解部分仍有推进价值。

## 层级与跨枝行为

FOLDER 可以同时组织节点与承诺自己的行为，ATOMIC 描述粒度不决定实现的独立性。祖先规则可能作用于整个范围、特定对象或特定条件；其语义作用决定哪些子路径需要兑现。只保留叶子会丢失有效约束，机械累加祖先则可能把不适用条件带入工作。

同一账户、配置或业务对象可能在多个入口被修改与展示。修改后重新进入或重开、连续动作后旧状态的保留、失败后的数据与界面状态，可能共同构成一个用户结果。单枝观察只涵盖其中一半时，另半结果仍欠。共享状态的权威来源、读写时机及刷新关系决定跨路径一致性；共同接口的格式相同，并不足以表达这些条件。

## 依赖字段与工作边界

原树的子层是初始能力候选。候选要能说明用户或下游取得什么结果、哪些相关材料足以理解它，以及如何在明确前提下判断它已成立。例如账户管理与文件导入可能共享登录身份，但登录合同明确后，各自仍有独立的行为结果与反馈。可独立交付不意味着没有共同前提，也不意味着能脱离应用单独运行。

同一能力的成功、拒绝、权限与状态保持条件共同决定它的完成依据，按场景逐项拆分可能把同一语义分散给互不知情的负责人。子树过大时沿已有子层继续分辨能力；跨枝操作则说明各局部交付和谁核对完整旅程。合并候选需要指出哪些行为必须一起裁决或交付，分开候选需要指出各自可取得的结果与反馈。反对一叶一项的机械规则，没有取消原树作为工作地图的价值。

dependencies 可能表示输入、真实状态、稳定接口或业务关联。解释它约束的具体动作：需要已发布实现才能继续的是实施依赖，需要共同语义明确的是决策前提，只在运行和验收时需要真实数据的是观察前提。稳定合同可以支持先行实现，真实服务与数据可能只阻塞后续观察；尚未确定的共享语义则可能让两个实现各自正确却互相矛盾。业务关联或场景使用同一对象，不能直接推出全部实现串行或归同一负责人。

共同前提的交付与业务能力的交付保持各自结束条件。共享持久化接口可以先提供验证、提交和读取语义，各入口再兑现自己的完整行为；“准备共同数据”也不能吸收所有业务的种子关系和权限要求。比如账户管理与文件导入都需要持久化：基础项可交付迁移入口与事务合同，账户项交付用户管理的完整行为，导入项交付文件进入产品后的结果。它们可以顺序实施，分别取得局部反馈，再由整体负责人核对跨能力旅程；不必为了共用数据库把全部业务变成基础项的实现清单。

工作项应让下一负责人知道要取得哪项能力、先采用什么成果，以及哪些结果尚需整体核对。把多个能力写进文档、再将全部实现与自查交给同一个基础 PR，保留了分类而没有形成这类责任边界。确需合并时，依据是必须共同取得的用户结果或共同裁决的未知，并说明合并后怎样取得各能力的反馈；根负责基础建设或实施者具备子 Agent 工具，不是业务合并的依据。通用的 [共享设置例子](../../braid-collaboration/references/worked-example.md)说明共享接口、局部实施与汇总责任如何连接，不提供任何 ARC 题目的实现答案。

修改已有应用时，沿同一结构用基线行为证据区分已成立且需保留、明确修改、缺失与尚未核实的能力。修改字段只界定显式变化，不替代整个允许范围；已有文件或页面也不证明行为已成立。能力负责人核对自己的既有数据和变化条件，整体负责人仍回查未分配义务和跨枝旅程。必要解释、来源与责任保存在已有工作材料中，不另造与原需求竞争的完整副本。

## 场景状态与图片事实

场景中的角色、先前状态、入口、动作、可见结果及例外，决定观察所代表的行为。正常启动必须具备的数据是产品义务；用户按正常流程建立的状态与仅供检查的数据具有不同来源。GIVEN 写着“已存在”未必要求 seed，检查中提前创建过状态也未必证明启动要求成立。条件与结果的关系由 [svc-verification](../../svc-verification/SKILL.md) 展开。

图片中的布局、层级、文字、控件状态与交互关系需要真实视觉观察才有依据，文字与图片的关系共同决定解释。无法看到的内容仍是未知，观察的方式由本次视觉能力与配方决定。图片里的实例值是否构成产品要求，取决于正文与场景；固定它或忽略它都需要相应语义依据。有效观察的适用范围决定能否复用，逐图重新开会话没有独立的信息价值。

## 实现选择与新增产品语义

默认规则、便利行为或例外可能改变对象、作用边界或前后状态。它与原承诺一致时，可以是合理实现选择；明确冲突时，设计及 API 合同中保存的解释也仍需纠正；真正歧义或目标变化涉及相应负责人和授权范围。共同定义保存已经成立的解释，而不是把待判断提案变成新的允许需求。

承诺、适用来源、重要解释与未知之间的关系使后续分工和验收可恢复。[覆盖回查](tracing-and-reviewing-coverage.md)展开它们与工作、候选及结果的关系。
