# Task Packet Information Modules

Use an information module when a distinct task-local semantic owner reduces reconstruction, stale-state, or conflicting-edit cost.
Keep the information inline in `packet.md`, a Plan, or a Slice while that is cheaper.
Module files may grow behind a stable entry and same-stem directory; file count does not define the module.

## Inquiry

Inquiry holds the current answer to a material question, its evidence, candidate explanations, and unresolved observations.
Keep facts and inferences distinct, including the scope and freshness that affect the conclusion.
When the answer changes the route, replace the superseded conclusion and retain reasons that prevent repeating an already rejected approach.
Record the next observation that could distinguish the remaining explanations; link raw evidence instead of accumulating search transcripts.
Diagnosis is an inquiry into a mismatch, not a separate required document.
Use [Explore](../methods/explore/index.md) to decide how to obtain the missing information.

## Design

Design owns the current coherent proposed solution, forces, material live alternatives, representative consequences, and residual.
It is a result surface; Task-map and Plan files own the process of producing or realizing it.
Use the cheapest truthful carrier—a diagram, pseudocode, prototype, or code may carry part of the design—without hiding material rationale or obligations.

## Decision

Decision records an authoritative choice separately from the evolving Design: subject and state, deciding authority and date, selected option, causal rationale, consequences, and reopen or supersession condition.
Mechanically shard a large register when that lowers editing and retrieval cost; keep one stable entry and do not confuse shard size with semantic modularity.

## Verification

Keep observations and judgments with the work they concern.
Add `verification.md` only when several results need a shared account of what is supported, what remains unknown, and what should happen next.
Verification can change the route at any point; it is not only a final Task phase.
Use [Verification and Validation](../verification/index.md) to interpret the evidence.

Do not create default Implementation, Delivery, Acceptance, Retrospective, Agent, Track, Phase, Slice, or generic module files.
Add a surface because its owner and management return are real, not because a template exists.
