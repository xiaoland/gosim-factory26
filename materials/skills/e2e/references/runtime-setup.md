# Set up the checkout's e2e environment

Read this before the first MCP session or application E2E command in a checkout. The Harness supplies `E2E_CONFIG_TEMPLATE` and `E2E_NODE_MODULES`; inspect the actual supplied config for supported targets and settings. Native interface details remain in `e2e guide setup` and `e2e guide mcp`.

Use the application service owned by this work item, its actual URL, and isolated application data. Do not operate another checkout's changing service or mutate delivery data. For an evolution or migration check, make the isolated service from an owned copy of the supplied business baseline, including the database and mutable business files/indexes; preserve that copy as the check's initial state. An empty database is a separate initialization case and cannot replace the baseline upgrade case. Create the checkout's ignored `.factory-e2e/` directory, copy the supplied template as `.factory-e2e/e2e.config.ts`, and link `.factory-e2e/node_modules` to the supplied tool dependencies. Do not overwrite an existing directory or historical evidence before establishing its owner. The config directory is the e2e project root; place application check files under `.factory-e2e/tests/`. Checks needed in the delivered application must be integrated into its actual tooling separately.

In every mcporter/e2e invocation, export `E2E_CONFIG="$PWD/.factory-e2e/e2e.config.ts"` from this checkout and `E2E_APP_URL` to the actual service URL. The config does not start the service. The supplied template consumes `E2E_BASE_URL`, `E2E_API_KEY` and `E2E_MODEL` injected by the executor; the selected endpoint, credential and wire model belong to that run's frozen configuration, not this skill. Do not print credentials or replace the route. The experiment's model-use restrictions and authorization apply to the inner runner too; it does not pass through Pi's Braid-session model guard. Manual MCP browser operations do not consume model calls.

Keep the supplied `workers: 1` in the actual TypeScript runner configuration and do not override it with parallel worker flags. This limits that runner's workers; it does not isolate server data or stop another responsibility's owned service/job. Close your owned sessions and finish or explicitly stop owned background work before handing off the execution responsibility.

Use the browser prepared with this runtime. The current addon supplies default Chromium; keep `web()` on it and do not install a browser during a run. Use a fresh owned output directory per acceptance attempt; inspect the supplied config's output setting and its supported override before running. The executor supplies `E2E_TELEMETRY_DISABLED=1`; keep upstream feedback and GitHub reporting disabled for this run.

For MCP connection identity and open/action/close handling, follow [MCP session lifecycle](mcp-session-lifecycle.md). Choose the attempt output before open and keep the entire connection environment/config/command/cwd fixed until your session is closed. Carry the id only in the session payload, not a newly exported environment variable. Change output only when beginning a new attempt after closing the old session.
