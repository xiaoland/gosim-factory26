# Executor-owned interactive E2E

Use the native e2e tool when the executor exposes it. The current application service must be an isolated application/data copy; open does not start it. This entry performs manual SDK operations without inner model calls. TypeScript runner acceptance remains separate.

Open with operation open and the actual service url, optionally a target from the config. Retain the returned opaque handle and outputDirectory. The executor selects the absolute config, command, cwd, complete child environment and output. You do not export E2E_SESSION, choose another model connection or change a live attempt's config/output.

Use discover with handle to read the actual session catalog; provide tool to inspect that tool's argument schema. Use call with handle, tool and args to invoke observe, locate, screenshot, grammar actions and project tools. Use semantic locate queries rather than parsing observation lines. Node ids remain valid only for the newest observation. For screenshot, the entry saves images in outputDirectory/screenshots by default; a saveImages path must stay beneath outputDirectory. Image data is retained in evidence rather than printed into model context. Inspect saved images and the actual response, not just the action name.

Always close your own handle after work, including after an operation failure. In scripts use finally; if close also fails, preserve both failures rather than replacing the original. The executor also attempts run-end closure before stopping its run-owned mcporter daemon. Only a confirmed close is marked closed. SESSION_BUSY means another operation currently owns this same handle; do not issue concurrent operations on it. Other handles remain independent.

The handle persists across shells, but not across a changed client/config/recipe or a lost SDK server. CONNECTION_CHANGED refuses changed inputs. SESSION_LOST or SESSION_ENDED does not silently reopen or reconstruct login/page state. Report the failure, then explicitly start a new attempt and redo the required journey if continuation is needed. Never use an old handle to infer a browser checkpoint. Each open creates a fresh owned attempt/output; the old attempt's reports are not its result.

The CLI projection uses the same shared client, not a second driver implementation. With the executor-provided FACTORY26_E2E_RECIPE retained, invoke the supplied tool Node on tools/owned-e2e.mjs with a JSON request matching the native tool, for example {"operation":"call","handle":"<returned handle>","tool":"observe","args":{}}. It returns JSON with isError and actual exitCode, and exits nonzero on errors. Native Pi execution errors are thrown as failed tools. Preserve stdoutEvidence/stderrEvidence and per-operation records. No direct e2e alias exists in this executor's default mcporter configuration; Context7 and Exa remain independent services.
