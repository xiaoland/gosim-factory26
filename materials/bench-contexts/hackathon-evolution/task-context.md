# Factory26 的 Evolution 附加任务约定

本文件是 Factory26 为本次 Evolution 实验提供的额外约定，不是官网发布的 requirements.yaml，也不是平台预置数据承诺。来源是完整公开 Evolution 需求、官方基线保留规则，以及用户在 2026-10-07 明确的“Agent当然需要增量创建要求的EVO数据”。官方需求与参考图片保持原字节，所有功能和场景的具体内容以所提供的公开 requirements 为准。

在官方既有应用上增量实现本次需求。先理解既有组件、接口与存储格式；为满足公开需求，可以重构或替换必要模块，不要求保留有缺陷的内部实现。仍须保留要求继续支持的功能、业务记录及身份关系、工作簿和工作表身份、原值与公式，以及未知字段；数据结构变化采用兼容迁移。不能清空、重置或整体覆盖应用与数据库，不能用新种子替换既有数据。基线携带的历史原生会话和工具证据只属于原运行，不是本次需求或验证事实；使用本次运行提供的独立会话与证据路径。

GitHub 当前公开 YAML 同时包含未修改功能及 Original/Modified 描述；修改项以 Modified 描述和当前场景为准。既有实现不代表这些功能已经满足需求，结合本次改动核对其依赖的既有能力。

公开需求中 GIVEN 所规定的初始工作簿、工作表、单元格和元数据属于交付初始状态。先核对既有数据；缺失时由生成 Agent 增量创建并持久化所需状态，包括 Sheet 场景要求的 EVO 工作簿，保留原业务记录与未知字段，不重复覆盖已存在的业务数据。不要假设评测方会额外提供缺失状态。只建立公开 GIVEN，不预先执行 WHEN，也不把 THEN 的预期结果写成初始答案。

交付前在原样应用核对公开初始数据和操作入口确实存在，再从该交付复制独立应用与数据，执行 WHEN 操作并观察 THEN。实现所需初始数据可以进入交付；验收产生的改名、删除、编辑等副作用不能写回交付。局部检查通过不代表原样应用已经具备这些前置条件，缺失或未验证的条件应明确记录。
