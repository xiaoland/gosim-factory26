# 运行分析 SOP

这是开发侧分析运行证据的方法，不注入参赛 Agent，也不规定其业务工作流。
目标是解释哪些可改变的因素造成时间、token 或交付质量问题，并把有证据的原因落到对应修复。
发现数量、阅读字数和报告长度不是完成标准。

## 先选择范围

先复用已完成审查及其证据边界，明确本轮新增目标，不重新做已有结论充分支持的终态归因。
运行审查包含两条互补路径：

- 结果因果审查：从交付、失败或评分现象追溯需求解释、决定、动作与反馈，找到影响结果的可改变因素。
- 全过程发现审查：按会话或工作项覆盖实际过程，开放寻找重复工作、等待、错误归因、消息误导、上下文膨胀、无效委派与恢复摩擦；即使后来修好或不影响最终产物，也记录它对 token、耗时和模型判断的影响。

可以单独执行其中一条，也可以组合；全过程发现不以预设故障列表或成本热点筛掉其余过程。
已有问题采用竞争解释来定向取证，尚未发现的问题通过完整过程阅读浮现。
全量审查需完成约定的可得材料，但高影响发现即时回传并处理，不等最后一份报告。
覆盖完整与因果成立分别核对，不能互相替代；局部发现不能自行推广到未读会话。

## 执行顺序

| 阶段 | 工作与产物 | 停止或升级依据 |
| --- | --- | --- |
| 1. 锁定对象 | 记录 run、执行/恢复链、冻结源码树、官方结果与原始证据入口；明确调查允许的操作。 | 身份对应后继续；版本不明先补来源，不拿另一版结果解释当前交付。 |
| 2. 建立唯一账本 | 优先复用已有索引，按原生会话/响应身份去重，记录缺失、已读、断点与省略。packet 只链接账本。 | 缺证无法取得时说明影响；文件已索引不等于内容已读。 |
| 3. 按目标组织阅读 | 结果审查沿交付向前追；过程审查按 session／Issue／PR 覆盖决定、动作、工具结果和后续修正。成本及异常分布提供导航，但不替代完整过程。 | 复用已完成单元；定向扩读说明竞争解释；开放发现允许尚无预设问题的阅读。 |
| 4. 有界并行 | 按工作项链或独立因果问题分 cell，明确独占范围、原文位置、返回格式和升级条件。用一个稳定、有界的阅读视图；精确重复引用原处。 | 子 Agent 负责局部取证，主审负责跨链判断；不让双方完整重读同一材料。显示截断须补读，不能计为完成。 |
| 5. 反证与终态 | 对照时间、PID、路径、commit/tree、真实退出状态；检查早期缺陷是否已修、其它成员是否承接、局部 PASS 是否覆盖所声称属性。 | 能改变修复方向的竞争解释未排除时，保留假设并提出最小补证；不以更多相似摘要代替判别。 |
| 6. 消费与收敛 | 为确证原因指定修复归属、实际改动、边界与下一轮行为证据。只做一次最终覆盖核对，回传完成消息。 | 定向诊断以决定可作出为止；全量审查需完成约定可得材料，明确缺失与省略。方法已写、代码已改、实际有效分开报告。 |

## 每个重要发现应回答

在报告中保留一条可追溯链：观察及原文位置 → 当时决定/实际动作 → 后果 → 根因与竞争解释 → 最终是否仍存在 → 修复与下一轮判别证据。
证据不足时写明缺什么，以及取得它后会改变哪项决定。
静态可达路径、运行实证、模型声明和隐藏评分关联分别标明。
应用缺陷用于检验通用方法或工具的不足，不把题目实现硬编码进 Harness。
工具输出、生命周期或能力接线的缺陷优先修对应实现；方法偏差才进入 SVC 或角色指引。

## 成本口径

以唯一模型响应统计新输入、缓存读取/写入及输出；reasoning 若是输出子集不重复累计。
原生会话与 OTLP 是同一响应的不同记录，不相加。
并行区间取并集描述墙钟，保留累计工作量作另一指标；失败请求、额度等待和工具时间单列。
给出已证冗余样本与归因边界，不将大上下文、高 token、全部重跑或无模型活动的间隔自动判为浪费。
缺少定价和计费语义时不推金额，不把历史冗余成本当作新方案保证节省量。

## 委派与可恢复交接

单个 session／Issue／PR 的局部过程阅读优先使用 gpt-5.6-luna medium/high；复杂跨链取证使用 Sol medium/high，Astra medium 负责整合与根因判断。
使用 fresh 上下文，提供原始材料入口而非整段主会话；局部报告保留决定—动作—反馈顺序、异常与反证、原文定位及未读边界，不能只有压缩摘要。
没有发现也保留覆盖记录；用少量原文抽查校准轻模型的遗漏风险，发现持续遗漏再调整分工，不让高价模型自动全量重读。
委派写清调查问题、独占目录、现有断点、读写权限、返回契约及通知条件。
高影响确定发现即时回传；最终同时返回覆盖/缺证、因果结论、修复建议与报告路径。
交接只保存当前决定、精确断点与证据位置，不再维护第二套总数或重复长摘要。
优先复用现有读取和索引脚本；只有重复出现的手工成本才提取工具，不预建通用审计平台。

## 审查自身的反馈

在已有 packet/cell 记录阶段起止、等待交接、截断补读和返工原因，足以回顾即可，不新增遥测系统。
没有真实阶段耗时就说明未知，不以被审 run 的耗时充当审查耗时。
