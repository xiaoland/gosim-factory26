## Capability Return

- Verification qualifies an owned claim through a discriminating observation
  and returns evidence, trusted-base scope, and residual; it does not create
  the claim or authorize acceptance/effects.
- Product/Technical Design owns claims; Test Design owns meaningful challenges
  and oracles; Implementation builds mechanisms; Verification executes and
  interprets them; the consumer owns disposition.
- Choose the smallest credible mechanism for the loss at stake. Determinism is
  not validity; same-context AI tests are correlated candidate evidence.
- Reuse qualified module guarantees by checking assumptions and consumer
  connection; requalify when their relevant basis changes.
- Verification activity remains distributed. Root `verification.md` is a
  pressure-created cross-return synthesis, never a final phase.
- Rough landing is one compact `src/sections/verification.md` plus a Working
  Protocol link. Full model: [`design/80`](../design/80-minimal-verification-capability-and-landing.md).

## Relations and Return

- Consumes `WP` effect/integration rules and constrains when evidence can
  authorize continuation, acceptance, escalation, or reopening.
- Meets `SA` at certificates and independence, and `TD` where design quality or
  personal taste needs a reviewable claim/observation rather than assertion.
- Returns a capability model for consolidated review; it does not centralize
  every local check in the root Verification module.
