## Status Correction: the First Dogfood Used the Wrong Boundaries

The initial study below is retained as a failure record, not as support for
profile admission. It made three coupled design errors:

| Attempt | Failure | Why it violates the delegation model |
| --- | --- | --- |
| telemetry discovery | it was a serial precondition for later analysis even though the Primary could directly use the local CLI/docs | no distinct advantage over the deterministic/direct alternative; it added a needless boundary and delay |
| historical packet-pattern audit | it examined prior Task Packets even though the requested evidence scope was real Codex Threads | no authorized consumer for the Return; a useful-looking search became scope drift |
| one Child across three large session snapshots | it combined three high-entropy local contexts into one cross-case synthesis | the Return was too broad for the Child's effective reasoning/context budget and too costly to validate; isolation weakened, while encrypted Child telemetry forced the Primary back into raw evidence |

Consequently, neither the repeated-boundary claims nor the Explorer/Executor
candidate language below may be used as real-session evidence. Explorer and
Executor remain the foreground *discussion candidates* from Sir's earlier
gleanings and the capability model, but profile admission now awaits the
corrected study.

### What This Study Observed—and Did Not

The study directly observed repeated **attention-partition boundaries**:
task-specific local audits and bounded implementation/qualification work were
given to Children while the Primary retained Task integration. It did **not**
establish the other two causal levers:

- Child-return text is sometimes encrypted in telemetry, so no counterfactual
  shows that a specialist trajectory improved a candidate more than the Primary
  or a direct tool would have done.
- The provider marks explicit concurrency unavailable. Multiple spawned
  Children do not demonstrate concurrent critical-path reduction; nor do the
  snapshots measure elapsed-time value, fan-in delay, or conflict/rework cost.

Trajectory shaping and capacity scaling therefore remain invocation-level
hypotheses to test. They are not reasons to infer additional presets, and they
are not established benefits of Explorer or Executor merely because those
names appear useful. A profile specifies a recurring work contract; a specific
Assignment must separately state which causal lever is expected to repay its
cost.

## Superseded Initial Profile Interpretation

### Explorer — supported candidate

The repeated economical boundary is not “do all exploration.” It is:

```text
bounded evidence/owner/constraint question
  -> progressive local search, source comparison, and noise filtering
  -> supported map + citations/handles + material uncertainty
```

The cases support attention partition for this boundary. Specialized search
trajectory and capacity scaling remain plausible but unmeasured invocation
hypotheses: the former needs a better-result counterfactual, and the latter
needs an independent ready frontier plus demonstrated critical-path reduction.
Its characteristic validator is relational: cited sources support the stated
map, relevant owner/constraint relations hold, and freshness/residual is
explicit. It has no authority to select product trade-offs or silently convert
findings into a system decision.

The generic name `Explorer` may be retained because it is familiar, but its
profile must contain this narrow return, search/tool guidance, and failure
behavior. Cross-repository truth audit is a pressure-loaded specialization of
the same profile unless future cases establish a distinct stable consumer and
validator.

### Executor — supported candidate with a strict use boundary

The durable boundary is a bounded realization-feedback loop:

```text
accepted bounded change
  -> modify assigned reality
  -> run task-specific discriminator
  -> adjust realization or surface a design mismatch
  -> realized change + proof + residual
```

The cases support the recurrence of this bounded loop, not a measured outcome
gain from delegating it. Local iterative state, specialized tools/feedback, and
sometimes capacity scaling are the causal hypotheses to test per Assignment—not
bulk-editing justifications. It remains unsuitable where the Primary must
continuously make cross-Task design decisions, effects overlap, or no credible
discriminator exists. The effect gate and actual proof mechanism remain outside
the role label.

### Not admitted from these cases

- **what-rules-should-be-applied-now**: no deep return boundary was observed.
  Applicable-rule resolution normally belongs to Primary progressive loading;
  it may later be a deterministic retrieval capability or an Explorer pressure
  specialization, but it has not earned a profile.
- **doc_writer**: the cases support semantic owner integration, not a stable
  low-coupling writing boundary. Without a supported delta and a consumer that
  can validate the carrier, the Primary would need to redo the semantic work.
- **Reviewer / QA / Validator**: real qualification mechanisms vary radically
  by scope. A reviewer can diversify/challenge or orchestrate a complex plan;
  it cannot become a trusted verdict by role. The case evidence does not yet
  show one stable enough return/validator pair for a generic preset.
- **Task-packet manager**: Task Packet is Primary-owned control state and
  Human coordination surface. Splitting its maintenance into a named Child
  would add a cross-state integration boundary without enough compression.

## Superseded Dogfood Execution

This study used three read-only Child Assignments. Their first two Returns were
locally useful, but the set as a whole is not a valid profile-discovery study:

| Child Assignment | Intended gain | Return validator | Result |
| --- | --- | --- | --- |
| telemetry discovery | attention partition over local acquisition mechanics | direct command/source inspection and bounded metadata check | found safe inventory/export/query/read route and freshness/privacy limits |
| existing-packet pattern audit | attention partition over corpus-wide packet reading | Primary spot-check of cited source files and admission constraints | found recurring boundaries and strong evidence against premature role catalog |
| session-boundary analysis | attention partition over selected evidence | Primary checked representative contiguous native refs in all three cases | identified structural boundaries only; return quality remains partially unobservable because child telemetry text is encrypted |

The first two returns were compact enough to validate without replaying their
whole searches. The third exposed a useful limit: evidence snapshots preserve
tool/lifecycle structure but not always intelligible Child synthesis. A future
profile must therefore make its own result carrier and certificate independently
available to the Primary; telemetry alone is not an adequate delegated-return
validator.

## Corrected Session-study Design

The Primary acquires the explicit local snapshots directly through the
deterministic telemetry surface. Then three independent Child Assignments run
in parallel—one exact session per Child. This is an outer evidence partition,
not permission to summarize an entire large session: each Child selects one
bounded delegation episode that fits its actual model/context capability. Each
Child returns one compact, non-quoting **case card**:

```text
one Task / one selected delegation episode
  -> Primary objective and bounded Child Assignment
  -> observable return/integration event and evidence horizon
  -> effect boundary, residual, and what the episode cannot establish
```

The Child must not synthesize across cases, select profiles, or infer hidden
return quality from encrypted telemetry. The Primary compares the resulting
small case cards and only then asks whether a recurrent profile boundary exists.
The return validator is citation/relationship checking against a small number
of contiguous native records. If that still requires the Primary to reconstruct
the raw episode, the case-card boundary itself fails and must be simplified.

### Result of the Corrected Study

All three sessions show a bounded local-information branch whose likely direct
benefit is **attention partition**. None supplies a counterfactual that proves
specialization changed result quality, and provider telemetry marks explicit
concurrency unavailable, so it does not establish capacity scaling. The
contrasting carriers are more informative:

```text
opaque completion message
    -> Primary cannot cheaply assess quality or integration

supported local map + effect declaration + residual
    -> Primary can consume and relation-check a compact Return
```

This is evidence for a possible Explorer-shaped **work contract**, not yet an
admitted SVC profile: a bounded, normally read-only information/constraint
question; progressive local search; and a supported map with source handles,
effect declaration, freshness/unknowns, and next discriminator. It must remain
distinct from the Explore Working Method: a Primary may use Explore directly,
and a Child using this work contract may combine Explore with other Methods.
The profile question remains open until this boundary is compared against a
direct Primary alternative and an Executor-shaped realization loop.
