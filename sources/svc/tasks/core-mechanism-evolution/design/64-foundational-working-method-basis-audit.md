# Foundational Working Method Basis Audit

- **State**: integrated; provisional basis completeness accepted in `D-075`
- **Consumer**: `WP × P1 / 31-DS`
- **Question**: whether Explore, Design, and Implementation form the current
  minimum foundational basis, and which remaining important behaviors need
  protocol/specialist guidance rather than another foundation
- **Inputs**: `D-058..D-067`, `D-070..D-074`, the Working Method comparison
  ledger, current SVC postures, and the promised closing concerns
- **Not decided now**: detailed Human collaboration, Decision support,
  planning/control SOP, project-truth consolidation, Agent work-system
  adaptation, specialist method routing, corpus layout, or source mutation

## The Three Accepted Transformations

| Foundation | Recurring pressure | Distinctive return |
| --- | --- | --- |
| Explore | material information needed to proceed is not obvious | key supported information and residual uncertainty |
| Design | intent, reality, constraints, resources, and taste do not yet form one coherent possible solution | coherent product/technical solution at consumer-needed resolution |
| Implementation | a bounded intended change is not yet actual and reality can resist it | actualized bounded change, realization feedback, and residual obligations |

Together they cover changes to supported understanding, possible product/system
arrangement, and actual product/system state. This is not a claim that all work
is linear or that every activity must name one method; the methods recur and
compose inside any useful return.

## Pressure-Test the Apparent Gaps

| Candidate | Why it looks foundational | Current decomposition | Remaining distinct need |
| --- | --- | --- | --- |
| Decision | produces a consequential commitment | Explore/Discriminate establish support; Design shapes alternatives/solution; authority makes the disposition; protocol records/integrates it | Human/Agent decision-ready collaboration guidance and typed authority, not necessarily a Working Method |
| Planning | produces a route through work | Task Packet owns linear Plan/graph topology; universal protocol selects returns, integrates feedback, and replans | compact work-control guidance and topology transitions |
| Review | challenges another return | use the method appropriate to the challenged claim; qualified verifiers and Human review provide independent observations | specialist reviewer/delegation design and evidence integration |
| Verification | produces qualification | Design the verification solution, Implement verifier/candidate, execute trusted mechanism, integrate verdict | `VF` capability, `VR` return, and Guardrails; rejected as foundation in `D-074` |
| Diagnosis | explains an observed mismatch | Explore framed around mismatch and causal discrimination | progressive diagnosis/Explorer guidance where recurring pressure repays it |
| Project-truth consolidation | updates canonical knowledge owners | protocol integration plus bounded Implementation of accepted semantic deltas | a closing procedure with semantic-owner and no-op rules |
| Retrospective / work-system adaptation | changes future Agent behavior after observing task waste | Explore the trajectory, Design an intervention, Implement it, later Verify effect | a domain-specific composed closing method/procedure with a future work-system consumer |

No row currently exposes a fourth primitive transformation. It does expose
several important procedures and specialist methods. Rejecting foundational
status must not make them disappear.

## Why Retrospective Comes Next

Retrospective/work-system adaptation has the strongest unresolved SOP pressure:

- Sir explicitly wants the Agent to find avoidable bottlenecks and resource
  waste after real work, then reduce recurrence through a script, linter,
  Working Method, routing rule, tool, or other intervention
- it has a non-obvious consumer chain: the current Agent produces a supported
  adaptation opportunity; Design/Implementation realize an intervention; a
  future Agent/work system consumes it
- it must distinguish necessary task difficulty from avoidable work-system
  loss and resist overfitting one episode
- it needs a subtraction/retirement path because every intervention adds future
  context, maintenance, and false-positive cost
- project-truth consolidation is a separate closing concern with different
  evidence and consumers

This makes it a useful next derivation even if it ultimately remains a
specialist composed procedure rather than a fourth foundation.

## Provisional Proposition

Treat Explore, Design, and Implementation as the current complete foundational
basis. Do not add Decision, Planning, Review, Verification, Diagnosis,
consolidation, or Retrospective merely because each has a recognizable return
or activity name.

Next derive Agent work-system retrospective/adaptation from its own cases and
consumer economics. Then compare the result against the three-method basis and
the closing-procedure need. Reopen the basis only if that derivation reveals a
stable management-useful behavior that cannot be economically composed.

## Human Disposition

Sir accepts the provisional completeness of the three-method basis, the
Retrospective consumer chain, and the route to derive it next. Sir also notes
that Agent work-system retrospective is still a new practice both in the
industry and in personal use, so the resulting model must remain low-commitment
and explicitly provisional rather than claiming mature best practice.
