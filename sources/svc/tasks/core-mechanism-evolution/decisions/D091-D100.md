# Decisions D-091..D-100

## D-091 — Corpus Navigation Uses Symmetric Directory Entries

- **State**: accepted at source-layout design depth
- **Authority and date**: Sir, 2026-08-16
- **Accepts**:
  [`design/87`](../design/87-symmetric-corpus-navigation.md)
- **Decision**:
  - Every navigable SVC Corpus semantic concept uses
    `<concept>/index.md` as its stable entry from the first landing.
  - Structural symmetry applies to node shape, not content volume. A sibling
    may have only `index.md` while another has pressure-proven depth; no empty
    mirrored topics are created.
  - Expansion adds content beside the stable entry and never changes its
    canonical address.
  - Atomic terminal artifacts such as individual templates or versioned
    migration notes may remain files; when one becomes a navigable family, it
    adopts the same directory-entry grammar.
- **Rationale**: A mixed file/directory grammar makes current expansion depth
  part of the navigation interface and forces Humans/Agents to remember which
  concepts have already grown. One symmetric grammar makes filesystem browsing
  compositional and keeps public addresses stable.
- **Reopen trigger**: Real source/lookup use shows repeated `index.md` paths
  create more ambiguity than they remove, or a semantic concept cannot receive
  a stable directory name without a false category.
