# 修改 SVC Skills

先读 [维护约定](AGENTS.md)，再从 `skills/` 下对应的 `SKILL.md` 定位当前问题的正文。
改动目标是让 Agent 更容易作出有依据的下一步选择，不以文档数量或规则数量衡量增强。

简短方法可直接维护在技能的 `SKILL.md`，需要展开的正文维护在其 `references/`；文档与任务包的可选模板各自维护在对应技能的 `assets/templates/`。
修改正文后，更新受影响的直接导航和相对引用；常用方法应能从 SKILL.md 一次到达，不要求读者先读多层索引。
已有方法页的相关链接用于选择下一步，不是要求预读整棵目录。
`svc-sub-agents` 保持自包含；具体角色职责和运行接线归消费者，不在通用方法中定义角色政策。

每个技能的版本元数据位于自己的 SKILL.md。
发布材料是选定的技能目录；不运行旧 Catalog/wheel 构建，也不复制 CLI、维护者指南、工作任务或开发环境。
目录名保留为技能名，并与 frontmatter 的 name 一致。
不设 Corpus 内容测试、盲读测试或提示词评分器。
编辑复核只证明材料层面的改动；对行为改善的判断需要获授权的真实任务与足够证据。

旧 CLI、PDM、towncrier 及历史 docs 留存其原有开发历史，不是当前技能的维护和发布指令。
完整开发侧 SVC 的同步需明确目标工作树与适用范围，不因本次 skill 改动自动发生。
