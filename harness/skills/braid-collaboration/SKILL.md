# Braid 协作

开始组织、承接或整合 Braid 工作时读取此技能。Braid 提供工作项、讨论、成员和代码协作入口；工作怎样分解、成果是否已经采用、原要求是否兑现，仍由成员根据任务与事实判断。对象关联使材料可定位，不能代替这些判断。

## 按成果组织责任

Issue 保留当前目标、范围、本项采用的关键决定和仍欠的义务，关联 PR 提供实现候选、审阅与实际证据。先确定下一位消费者要取得什么结果，再划定可以独立推进的工作。稳定接口可支持消费者并行实现；必须取得真实数据或服务才能观察的行为，则需在相应结果可用后核实。共享状态或完整操作需要汇总结果的负责人，但不要求这个负责人亲自实现每一部分。已有工作能承接时直接复用，增加对象只有在责任、交付或判断边界因此更清楚时才有价值。具体选择见 [组织工作](references/organizing-work.md)。

原始要求说明产品承诺，项目文档保存已采用的共同定义，task packet 保存当前判断与下一步，description 给出当前工作义务或候选，讨论交流本次变化，原始输出保存观察。它们变化的原因不同，互相镜像会使消费者难以判断哪份仍有效。非简单工作开始或接续时读取 [svc-documentation](../svc-documentation/SKILL.md) 与 [svc-task-packet](../svc-task-packet/SKILL.md)，先取得原要求、适用共同定义和已有 packet，用 `git rev-parse --show-toplevel` 确认当前实际 Git clone 的工作树根，再在该根下的 `tasks/<task>/packet.md` 接续判断与下一步，不能等代码完成或会话将结束才补记。两项技能持有详细方法，不在每个工作项重新造一套文档。

共同文档、项目阅读入口与任务材料建立在当前实际 Git clone 的工作树根下，随适用代码版本交付。根负责人先发布共享定义、项目阅读入口和根 packet，使依赖它们的成员能从共同提交取得；PR 负责人将当前 packet 随候选提交和 push 发布，整合后仍可在共同分支发现。当前 clone 外的私有笔记和运行证据可以保留，但不能代替要交接的 packet。项目根 AGENTS 只导航产品、技术、操作与任务入口并记录适用开发规则，不复制文档正文或 Harness 的角色、模型与实验配方。文件已写、已提交、已发布和消费者已采用分别核实；路径存在或读过技能不等于完成采用。

## 交接要能继续工作

交接让接收者知道要完成什么、依据与成果在哪里、哪些前提成立、还有什么缺口。发布成果结束了生产部分；实际接入、证据适用和剩余义务还需分别判断。接收者已采用接口继续实现或返回可用成果时，就有承接依据，无需再制造一轮纯 ACK。只有消息已送达、对象已关联或 PR 已合并，还不足以证明消费者采用了正确结果。

局部排除可以合理，整体要求不会因此消失。整体负责人保留剩余义务，直到合适的工作项实际接手，或有权改变目标的人明确变更原要求。变化发生时更新共同定义，并找当前真正实施、集成和检查它的消费者；通知说明差异、影响与下一动作，接收者判断采用、无影响或具体阻塞。只通知原始生产者可能遗漏已经交接的消费者。具体分支见 [交接与变化](references/handoffs-and-changes.md)。

Braid 成员承担独立工作项，原生 sub-agent 帮助当前成员处理局部工作。需要原生委派时读取 [svc-sub-agents](../svc-sub-agents/SKILL.md)，交给其它成员的同一成果通过工作项协作取得，避免另启一份竞争实现。咨询独立判断时保留会挑战当前解释的事实，而不是先过滤反例；角色选择和调用时机仍遵守本次配方。

## 消费结果后再结束

收到结果后分别判断：原要求和仍欠义务是什么，现有判据足以说明什么，实际候选在什么条件下取得什么结果。已有有效结果可以直接采用；候选、共享代码、数据或条件变化时，按受影响范围复查，而不是因 head 前移就全量重跑。检查设计与结果解释读取 [svc-verification](../svc-verification/SKILL.md)。覆盖不足的正确结果支持局部接受，不支持把未观察的并列行为一起计为完成。

ready、merge、close 是不同动作。结束工作前让有效成果可供采用、未完成事项有明确责任与入口；状态操作成功才把它写成事实。讨论围绕可独立结束的问题，结束前将仍有效决定保存到当前材料，保留未决义务。Braid 的 resolve 接受讨论根 ID，折叠当时的历史前缀，新回复仍可见；因此 resolve 不是删除证据，也不是关闭工作项。没有新事实、决定或行动时可以停止维护，已经消费的回执和普通提醒不要求反复公开总结。具体判断见 [接受与关闭](references/accepting-and-closing.md)。

[编辑器与导入器的完整例子](references/worked-example.md)贯穿上述判断：分工合理但义务尚欠、共同定义已经发布但消费者尚未采用、局部结果有效但不能支持整体关闭。例子同时保留正确承接、有效结果复用与合理停止，避免把协作变成永久催问。
