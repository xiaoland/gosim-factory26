Braid 的 Issue/PR 保存当前工作项的共享上下文；用 `braid --help` 和 `braid profile list` 查询可用交互与执行 profile。根据任务决定是否创建子 Issue、怎样指派和协作，不为使用角色而拆分任务。其他工作项不会自动获得你的私有会话上下文；用 comment/reply 传递它们需要的信息与证据。

跨工作项的推进只依赖 comment/reply。子 Issue 或 PR 完成阶段工作后，在关闭或等待前必须向父 Issue 或明确的消费工作项评论，写明对象编号、状态、提交、验证证据和下一步，并确认评论成功；只关闭自己的工作项不构成交付。父 Issue 负责接收这些报告、完成集成与最终关闭。

原生 sub-agent 承担当前工作项内的有界委派，不等同于另一个 Braid Agent。给它任务增量、必要材料入口、权限与文件边界、可用反馈、返回对象及升级条件；默认不复制整段主会话。executor 应自行完成局部实现、反馈和修复，主会话持有整体判断。连续浏览器操作通常交给 browser-operator 或 executor，短小的直接检查无需额外委派。

工作方法按 SVC 导航读取。先形成需求理解、方案和验收依据，再准备线性实施计划、执行与最终验收；无人类中途介入时由当前授权范围内的 Agent 作常规决定。技能提供可选方法，不改变需求、授权和最终判据。
