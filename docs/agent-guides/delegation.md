# 开发 Agent 的委派与接续

本指南面向开发 Agent。安排复杂委派、跨会话协调或实验恢复时按需阅读；常驻核心约定见 [AGENTS.md](../../AGENTS.md)。

在 task packet 中保存用户要取得的结果、当前决定与授权、完成依据、负责人及证据入口。按可独立采用的结果划分工作：简单工作直接完成；有复杂证据路径或需要多轮局部反馈的调查、实现、操作可交给 sub-agent；需要独立持续上下文和用户跟进的工作可在获准后交给独立会话。委派应节省调查、执行和结果采用的总成本，调用方无需先查明全部文件和操作步骤。

紧密相连的调查、必要源码修复、准备、实际操作和验证，由同一执行负责人完成。权限应覆盖已授权结果所需的共享源码改动；文件分工用于协调并行修改，不把每个文件变成审批边界。执行者保留其他人的改动，自行解决范围内的可恢复失败；涉及缺失的用户事实、授权变化或重大取舍时再升级。主 Agent 负责总体判断和结果采用，并继续独立工作。

独立会话持续持有同一结果的责任，普通失败和中间产物交付不改变负责人。调整其任务前，先核对当前 packet 和该会话最新的人类决定，保留已有授权及有效进度。后续消息只传会改变执行的新决定、重要约束或依赖变化、必要问题与可采用结果，相关更新合并发送；普通进展写入任务记录，避免反复催促、重申许可或要求逐步确认。通过完成事件或适当间隔关注状态。

已获准的依赖协调由相关负责人直接完成，主会话不重复中转同一技术往返。共享组件交付时说明实际可消费的版本与剩余依赖，消费方据此冻结制品。反复出现例行升级、未完成组件导致重新冻结或等待局部指令时，先补足执行权限或合并负责人，不继续增加交接环节。

例如，已授权“恢复并启动一次运行”时，同一负责人完成来源核实、必要修复、制品准备、启动和实际读回，既定实验边界与必要启动条件继续适用；一般 DX 整理仅在解决具体阻塞时进入关键路径。共享运行、外部提交等相同可变目标同时只有一个执行负责人。确需更换负责人时，才交接当前决定、进度、证据入口和在途操作，核实由谁继续；缺少回复不等于旧操作已停止。

采用结果时核对足以支持结论的少量实际观察，说明其范围与未知；原始日志保留入口，不默认重读全部材料或追加相同调查。线程链接、交付声明和制品 hash 各有证明范围，不能单独证明用户结果已达成。对用户区分已委派、正在执行和结果已验证，达到完成条件后收尾。
