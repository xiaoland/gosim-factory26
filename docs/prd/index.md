# 产品说明

Factory26 用于开发和比较能依据需求生成或修改应用的 Coding Agent Harness。Coding Agent 维护仓库；运行时 Agent 消费冻结需求与工具材料，完成业务应用。实验应能追溯输入、实际程序、模型、应用、评测结果和错误来源。

## Harness

LLM 负责理解需求、选择工具和组织协作。Harness 提供执行环境、原生会话、角色与技能材料，不按需求编号自动拆分工作或判断覆盖完成。

团队实现使用 Braid 的 Issue、PR、成员和讨论。根 Issue 保存本次需求入口，Agent 按需要创建和指派后续工作项；Issue 负责需求与方案，PR 负责实施与候选验收。Braid 工作项间协作和 Pi/Codex 会话内子代理分别维护上下文和生命周期。

SVC 以独立技能文件提供文档、任务包、协作和验证方法。技能正文按需读取，角色和任务提示只提供发现入口；共享成果通过应用 Git 与工作项讨论交付。原生 Pi、团队实现和职责对照见 [Variant 索引](../../variants/README.md)，模型、工具和角色由所选实现维护。

## 实验平台

Lab 以一次实际执行（run）为控制单位，负责装配、派发、观察、停止和保存结果。使用者选择 variant、target、task 和模型配置；复杂策略与多阶段任务使用同一 API 的普通 Python 程序。

运行状态、Agent 活动、应用交付和评分分别展示。Console 读取保存记录和 OTLP；缺失的费用、用量或现场证据保持未知。恢复必须明确继承了哪些应用、数据和会话，具体行为见[运行手册](../deployment/index.md)。

## 评价边界

独立生成仅使用允许的需求与资源。Agent 可以检查和修复自己的应用；外部评测消费冻结应用的独立副本，隐藏反馈不进入仍在生成的 Agent。主动依据外部反馈修复的实验须标明 `oracle/dev-only`，不能混作独立生成结果。比赛评估通用 Harness，不使用预制赛题答案或修改评测器来适配应用。

低分或失败用例可以是有效结果；安装、执行或评测中断须记录具体故障，不能当作有效零分。比较结果时同时核对输入、程序、模型、应用与评分身份。客户端 token 统计和费用估算不替代供应商账单。

各实现的源码存在、打包成功与完整生成收益是不同事实。公开源码包括尚未完成实际验收的成果；当前限制和实施依据保留在[工作记录](../work-index.md)及组件说明中。架构责任见[技术说明](../product-tdd/index.md)，历史结果见[报告索引](../../runs/reports/README.md)。
