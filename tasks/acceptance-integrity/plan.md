## 预演已提前收敛的接口

- 明确点名的收件人是具体成员。评论保存和投递是否可达分开报告；改派后的旧名字不可达，不转送新负责人。CLOSED/MERGED 的现任成员仍可在运行内回应。
- PR 引用发布分支，ready 表示草稿状态，不读私人 clone 或隐含宣称已验收；merge/recovery 使用该 PR 的 base/head 与 Git 原子更新。
- Factory 只在正常静止且根 CLOSED 后交付 main；根 OPEN 时保留未完成和现场。这会减少“生成成功”数量，但使该状态忠实于完整交付的前提。
- ZIP 去掉 node_modules/.bin，因此要有现有方式的 CLI 包装；检查目录自己解析冻结依赖；Chromium 版本与 Playwright 配套。链接使用应用目录的普通 .gitignore，不让 Braid 引入 Node 专属规则。
- SVC 以问题直接导航。正文要帮助形成和修改判断，不以换术语、加模板或增加必读层级代替方法。

完整的独立预演记录位于各 cell；未运行过的边界不会标记为已通过。
Git ref 冲突和关闭期间的新消息仍是实施中需要谨慎保持的并发边界，优先沿既有事务、队列与恢复机制修改。
