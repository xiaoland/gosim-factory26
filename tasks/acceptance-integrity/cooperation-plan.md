# 协作体验：实施计划与开工影响

2026-09-27。技术与验收方案已获用户“同意……继续推进”，本文件属于实施准备，尚未开工。
根检查评论是 Braid 以协作者身份发出的普通提醒；内容不代表业务裁决。

## 交付边界

交付自然回复与交接、持久关注、可读历史及根五分钟提醒这条完整协作链。
不扩建 GitHub Actions、审批引擎、provider 内部 sub-agent 生命周期或 SVC；不改当前正在使用的冻结制品。
根 OPEN 不再因暂时空闲自然结束，会使运行更长。关闭根或显式停止仍可结束运行；故障继续报告。这是已确认的可见产品变化，不另加隐含时间上限。

## 实施顺序

| 顺序 | 实施面与完成条件 | 所有权与依赖 |
| --- | --- | --- |
| 1 | 统一新数据结构和函数契约：关注、协作活动、Braid 评论作者、根空闲起点；旧记录只迁移可证实身份 | 主 Agent 负责 migration 与接口整合；先确认预演指出的身份接缝 |
| 2 | 对象写入及收件：创建/指派/评论/邀请建立关注，显式退出，按动作合并收件，记录活动，移除父项状态通知及普通关联广播 | 对象与 CLI 实现为一块完整责任；保留关联 Context 依赖更新，不直接删除所有跨对象事件 |
| 3 | 已关闭成员普通联系、忙碌时输入保留、交错收尾与身份复核；原有 @ 回执复用同一实际投递 | 主 Agent 负责 Store/group；依赖第 2 步的收件契约，避免两个实现者同时改 Store |
| 4 | 根五分钟检查接入 local 主循环；系统评论进入同一对象/收件路径，故障判断优先，OPEN 空闲等待下一时点 | 主 Agent 负责 local 与计时持久状态；依赖第 2、3 步完成后的真实通知行为 |
| 5 | view/timeline 和关注操作、简短持续指引、权威文档更新；整合构建与真实协作操作验收 | CLI/context/docs 由对象实现责任人贯通，主 Agent 验证运行效果 |
| 6 | 冻结新制品，WSL Lite 两题并行取得生成、完整评分和过程证据；汇报后按既定授权边界处理后续 Hackathon | 实验目录和制品独立，复用 runner/browser 依赖；不使用参赛额度、不启动新官网矩阵 |

实现阶段是否委派由最终独立工作面决定，不为并行数拆开同一事务的逻辑。
独立预演由 gpt-5.6-luna/high 执行，专查计划与实际接口，不把阅读代码当行为验收。

## 实施前要收敛的接缝

- 当前对象创建先预留具体 member_login，再异步建立 assignment。关注键必须覆盖这一间隙，不能因关注而要求同步启动原生 Agent。
- 普通收件和 @ 共用联系人路径后，关闭/休眠唤醒必须沿原具体成员，不能把 source 对象的状态当作 recipient 状态。
- 关联正文是 PR 当前 Context 的一部分。移除普通广播不能让 Context 保留旧正文；关注投递与投影失效分别处理。
- 根计时核对 actual turns、队列和恢复状态，避免 agent_instances 的 idle 值掩盖仍在运行的 provider 执行。
- Braid 系统作者必须在创建、CLI、Context 和历史中一致显示。系统评论不新建可指派成员，也不借用 root 的执行身份。

## 验收与证据

沿用已批准的 [验收矩阵](cooperation-design.md)，不新增 Factory/基础设施测试或模拟 provider。
先完成构建和真实 CLI/原生协作操作，记录实际身份、评论、收件、原生输入及对象状态；五分钟使用真实等待，不缩短生产阈值来声称通过。
协作操作与 benchmark 分开：操作验证能力契约，Lite 衡量 Agent 是否采用能力以及完整应用结果。不能为触发场景而临时改写 benchmark 的产品要求。
无法由自然运行覆盖的场景如实标注未覆盖，以已授权的实际协作操作补充；不把没有行动直接判为没收到。
正常运行由脚本等待终态，主 Agent 在明确故障或需要判断时接手。

## 独立预演收敛与待开工状态

gpt-5.6-luna/high 已完成 [独立预演](cooperation-preflight.md)。主 Agent 对其中剩余技术决策已收敛：

1. 关注主键采用稳定 member_login；新增 Assign 与投递事件携带对应目标身份，消费前事务核对。旧数据不补造未保存的历史身份快照；当前冻结实验不升级。
2. 普通回复按收件目标自己的状态选择开放输入或关闭后联系。待物化身份保留输入；确定不可达的地址留原因并结束该投递，不让无效 pending 永久堵住计时。
3. 关联关系/外部 description 的既有失效路径保留；关联评论变化在下一次合法输入前更新完整 Context，不以投影刷新偷偷恢复已取消的普通广播。
4. 根空闲资格只计入根及当前成员的持久输入、执行、恢复状态；子项活动不阻止检查。计时与到期评论在同一事务核对、更新。
5. Braid 系统作者单独存储和显示，不建成员、不借 root 身份；普通关注投递不变。

上述决定已同步技术方案，无新的产品范围请求。计划与预演完成，当前等待用户针对本计划的开工确认；尚未修改源码、启动验收或提交。
