## 修复优先级与本轮实验判读

第一优先级是让交接的投递目标成为可执行事实。沿用当前能力的最小修复是根在派工时指定根 Issue 编号，子任务把完成/阻塞评论直接写到负责整合的 Issue；若要支持 GitHub 式 `@成员`，则需要实现并验证该语义，而不能只在提示词里暗示已经支持。根收到后再按既定依赖指派下一批。

第二，原生可指派目录应使用与 CLI 相同的候选规则，排除 `root-only`。否则根会继续安排一个工具明确不允许执行的交接流程。

第三，在交付边界区分“调度静止”与“根负责人确认完成”。尚有未完成目标时应恢复协调或保留明确的未完成原因；单纯把根 Issue 关闭也不能代替应用验收，Braid 无需负责判断产品合格。
