# Braid 协作能力验收方案

本页是用户于 2026-09-21 同意的新增行为验收设计，不是已运行结果。原则沿用用户的 [V&V 方法](../verification-system.md)：从产品约束选择观察结果和 Oracle，区分验收与诊断证据。既有完整 Keep 32 项、生成冻结后外部评测及每次实验后汇报的标准保持不变；先完成本地检查，再按已批准范围执行模型实验。

## 需要证明的行为

| 行为性质 | 条件与观察结果 | 最小可信边界 |
| --- | --- | --- |
| 讨论关系真实、可回看 | Issue 与 PR 均创建原评论和回复；通过真实 CLI 读回同一 thread、稳定 ID 与正文。删除原评论仍保留回复和定位。跨对象错误回复被明确拒绝。 | CLI → SQLite → canonical Context，沿已有集成测试扩展。 |
| 上下文整理生效 | hide 附理由后默认输入无原正文，身份和理由保留，显式回看仍可读；resolve 折叠旧讨论，新回复仍可感知。unresolve 不复活已删除或另行隐藏的正文。 | renderer 与实际 provider 输入档案共同检查；不能只看数据库字段。 |
| 自编辑无需等待偶然外部输入 | Agent 自己改 description 或 hide 已见内容；不再注入其它消息，也能获得当前 Context 并继续。让 provider 结束分别先于、后于失效处理发生，结果都成立。旧 writer 后续写入被拒绝。 | 确定性 provider 控制顺序，加真实 adapter 场景验证输入替换；替身不证明真实模型行为。 |
| 回复送达正确消费者 | 无直接关联的 A 在 B 的讨论发言，B 回复；A 获得稳定来源引用并能读取实际回复。A 的物理会话替换或 runtime 重启后仍可消费。无关 C 不收到该讨论。 | 真实对象事务、持久队列与实际派发输入；不得仅检查事件行数。 |
| reaction 是有归属的轻消息 | 不同作者对同一 comment 添加/撤回表达，读回目标、作者和当前表达正确；重复添加不制造重复状态。自身回声不造成持续空转。 | 实际 CLI、Context 和有界运行的可观察执行。 |
| Issue 关系不强制分解 | 可不拆子 Issue 完成交付；可创建、关联、解除父子关系并读回引用，环被拒绝。创建父关系不复制全文、不导致审批或关闭传播。 | 对象边界及完整交付场景。 |
| 同类 Agent 真正独立运行 | A 保持活动并创建 B，B 在 A 结束前实际执行；分别覆盖 Issue 与 PR。重建或中断 A，B 的物理会话与工作仍持续。B 运行中关闭后仍正确收尾且不重复。 | 有屏障的确定性 provider + worktree/会话输入证据，替代依赖 sleep 时长的脆弱测试。 |
| 协作状态不能冒充交付 | 所有讨论 resolved 或有赞同 reaction，但产品候选没有满足现有交付条件，仍不能封存成功；原 merge 恢复、实际 ready commit 和 delivery commit 对应关系保持。 | 保留已有两 PR 交付/恢复检查，加真正改变决策的反例。 |

自动测试不要求模型一定选择某种拆分、固定消息顺序或某个实现算法。对关键 Oracle，用有目的的破坏检查确认它能发现漏送消息、旧正文残留或同类串行化；满足行为性质的等价实现应继续通过。

## 执行与证据

先运行对象/CLI/迁移和确定性 runtime 检查，再执行构建及受影响的 Factory 消费者检查。迁移检查从当前 v4 的已有对象升级，确认 ID、正文、PR request-id 和既有证据不丢失。已知历史 Clippy 失败不能写成通过；若新变更触及其边界，区分新引入问题与既有问题。

真实 adapter 接入验收沿用既有 Codex/Pi 受控场景的方式，新增自编辑和会话独立性证据，冻结输入和实际组件来源。自编辑场景让 Agent 通过真实 CLI 把 description 中唯一旧标记替换为新标记及后续可观察任务，不再注入其它外部消息；验收新原生会话的实际输入及后续任务结果。只读 Braid context.md 不足够：Codex 核对新 thread 注入记录，Pi 核对新 session 实际发出的 prompt，避免把 adapter 暂存当成模型已接收。provider 原生 sub-agent 未接通的部分单独列为未知，不能用宿主配置或无模型替身声称已验证。

完整生成与 bench 使用同一独立 variant、比赛指定模型及明确的运行入口，不自动扩大到多后端/多并发矩阵。先固定输入和验收范围，再开始一次实验；无论成功失败都停止并报告。分数是生成质量证据，消息/上下文/隔离性质另有针对性证据，二者不能互相替代。

验收报告给出实际结果和未成立项，诊断按问题链接到 CLI 读回、对象身份、实际输入、原生会话和交付源码。准备好材料不算通过；没有执行的检查写明未执行。现阶段上述所有新增检查均未运行。
