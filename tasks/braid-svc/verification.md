# 验收设计与证据状态

状态：用户已确认本页完整验收方案，并指定后续一段时间持续沿用。范围与判据没有实质变化时，不重复请求复核；仅在出现实质变化时说明原因并复核变更部分。实施门槛由 [plan.md](plan.md) 维护。

## 真实 bench 交付验收

建议首批四个 variant 各独立生成一次 Keep，冻结后执行官方全部 32 项测试：codex-svc、pi-svc、codex-svc-braid、pi-svc-braid。同一批固定模型、需求、benchmark、核心版本和实际组件源码；不同 variant 只切换声明的组件。不得读取外部测试指导同一次生成，不修补冻结应用以补齐成绩。

这一批证明接入和闭环可用，不足以给不同 harness 的效果作统计排名，也不等于完整 ARC-bench 总分。若其中出现基础设施失败，修复后使用新 run 重做受影响的验收；若是应用测试失败，则保留完整成绩与诊断结论，不以零失败作为接入验收门槛。

每次验收要求：真实 native core 使用比赛模型；生成自主结束且完整终态可识别；交付树来源明确并冻结；官方 32 项均有执行终态，跳过或缺失不算完成验证；原生证据、组件源码、评测结果和诊断入口能关联到该次 run。Braid 两组必须实际经过本地 Issue/PR CLI 与交付分支收敛，冻结应用等于返回 commit 的导出内容，WSL 评测副本及报告归属同一应用哈希。

另用两个短受控场景分别运行真实 Codex app-server 和 Pi：关闭 SVC、保留 Braid，检验 CLI 可用、上下文替换、旧 turn 拒绝及会话归档。这补充四组均开启 SVC 留下的独立性证据，且不把短探针计为 Keep 成绩。纯核心的配置和隔离检查只证明启动边界；未在本批跑完整 bench 的组合不宣称取得了新成绩。

WSL 冻结应用 4 路独立评测已有证据，可复用 runner 与浏览器缓存；各份评测仍使用官方 1 worker。持续模型生成并发没有同等证据，不能将评测并发结果代入生成能力。

## 产品行为排障矩阵

这些检查尽量从真实 CLI 和可观察状态进入。确定性 provider 可用于故障注入，但其通过不能替代上述真实 bench。

| 场景 | 需要证明的可观察行为 |
| --- | --- |
| SVC 开/关与两个核心 | user scope 仅有批准的导航；关闭 SVC 的 braid 仍可操作对象与运行，纯核心没有 braid 必需依赖。 |
| comment create/hide/unhide/delete | 对象身份稳定；按既有事件规则更新后续上下文，隐藏/删除正文不进入重建后的模型输入；恢复隐藏正文有效；删除保留墓碑。 |
| description 与既有正文修改 | 按根对象、关联对象和 writer 来源触发自动失效或下一 turn 更新；完整重建的新物理输入包含当前正文而无旧内容；逻辑 group/worktree 保留，不要求显式 refresh。 |
| 自身与其他 Agent 的写入 | 自身回声不自打断/循环唤醒；下一次正当执行自动获得最新 Context；其他受影响组不被整体 Agent-origin 过滤。 |
| PR 与 Issue 关联 | 同一请求 comment 幂等建立 PR；保留 1:N / N:1 表达能力；PR 使用当前直接关联 Issue；关闭 Issue 不继续暴露其完整正文。 |
| 旧 turn 与断连 | 失效 turn 的后续控制操作不能污染新状态；Unknown 不变成成功；恢复保留对象与工作区，无重复逻辑执行；已消耗的失效会话参与计量，但不以其中断状态代替整个 run 的完成判断。 |
| 无人值守收敛 | 按 design 的根 Issue/PR 责任完成交付；创建、实施、接受/完成、合并及交付树选择不存在隐含人类操作或固定角色往返；一次 turn completed 不等于整个生成结束。 |
| 合并与恢复 | 两个 PR 的产物同时进入交付 commit；冲突、提前 close 或 finalization 未结束不能成功冻结；Git 已更新而对象状态尚未更新时可恢复，不重复合并。 |

两个真实核心受控场景须捕获新旧 session 的实际输入及相同 group/worktree 身份；只改数据库 revision、只用确定性 provider，或自然 bench 未触发重建，都不能替代这项证据。

## 诊断独立验收

样本一采用 [inquiry.md](inquiry.md) 中的真实 REQ-2.2 失败。入口应能在少量定向查询内指出失败层、预期和实际差异、支持假说的页面/源码、尚不能判断的归因，以及下一项区分性检查；不先读取完整 rollout。

样本二采用已保留的 Playground 运行事件，证明默认界面区分心跳、有效进展、观测过期与终态，不能根据 0/N 分数判断停滞。

新 bench run 再验证工作项/原生会话/源码/评测的身份映射。若没有 traceability，必须明确显示未建立关联；若有，注明生产者和版本，不把显式记录当作自动证明的因果链。由单用例证据进入 SVC match/trace 后仍能回到准确的原生会话。错误的 evaluation ID、native 哈希或陈旧组件制品必须拒绝关联或标为未知，不静默采用最新目录。

由未参与入口实现的 Agent 使用这些入口复查真实样本，记录得到结论所需的查询和仍需人工拼接的信息。通过条件是证据足以区分竞争解释并定位下一检查；行数、日志数量或任意固定查询次数不作为质量代理。
