# Sheet 全量运行审查方法复盘

本复盘依据已完成审查的覆盖账本、交接记录及实际操作，不重新阅读原始运行，不增加测试或实验。它讨论开发侧审查方法，不讨论参赛 Agent 应如何实现 Sheet。没有本次审查各阶段的可靠耗时日志，因而不编造分钟数、阶段耗时占比或预计节省比例；原运行的模型/工具时长也不能当作审查耗时。

## 核心判断

Sheet 审查慢不只是数据量大。规模确实构成下限：263 个唯一原生会话、24,942 条记录、33 个工作项、401 条评论、624 条活动，外加 13 次执行、恢复日志、9 张参考图和13张最终截图。初扫得到约1084万字符独有 thinking、1377万字符工具结果、1361万字符用户输入。这不是只读 PR 摘要就能覆盖的材料。

另外两项成本同样重要。第一，因果链跨会话、角色和重启：早期失败后来可能修复；一句“全绿”可能来自旧候选；一次服务死亡可能由另一负责人清理触发。第二，审查自身存在可压缩的操作成本：长输出被截断后补读，多套渲染与进度描述并存，持续追加历史进度使当前状态难辨，最后再统一计数。不能将所有这些成本归给材料规模，更不能因过程长就断言分析更深入。

本次用户授权的是“全部可得材料完整审查”。因此每个有实质内容的会话都必须完成语义阅读，不能在找到几个高价值根因后停止。这个覆盖义务不应成为每次运行后的默认流程。

## 哪些属于这次全量授权

逐一完成263会话、审完关闭后的无行动通知、核对所有可得执行日志、补齐每处阅读截断，都是此次完整覆盖承诺的组成部分。即使某个迟到通知很可能没有新信息，也不能仅靠模式猜测就记作已读。精确相同文本可以引用已读原文，但语义相似不是省略依据。

普通运行复盘应先回答一个明确问题，例如“为何停止”“为何重复全量检查”“某失败在最终树是否仍存在”。默认不需要重建全部历史，不需要每次浏览所有截图、所有无行动会话、所有归档副本，也不需要为了证明认真而输出逐会话长摘要。只有来源不可靠、缺失可能改变结论、异常跨多个角色反复发生，或用户明确要求全量审计时才升级范围。

## 可复用的分阶段SOP

### 1. 先确定要作出的决定与证据边界

记录运行身份、最终产物、用户问题、允许的读写范围，以及结果将影响什么决定。明确是定向诊断还是完整审查；列出两个或更多可区分的解释。例如“产品逻辑失败”与“运行期间依赖被替换”需要不同证据。

停止条件：已取得足以改变决定的直接证据且主要竞争解释被排除，可以结束定向诊断。升级条件：来源或终态不清、现有材料互相矛盾，先补来源，不急着扩大到全部会话。

### 2. 建立最小来源清单和唯一覆盖账本

优先取得执行状态、最终commit/tree、工作项和关键原生会话。多归档时先按稳定身份去重，只有发现差异或需要完整性保证时再做完整内容核对。账本为每个阅读单元保存来源、状态、精确断点、截断与省略；只有完整且已消费的单元进入总数。packet引用总账，不维护第二套人工数字。

停止条件：证据源与产物能对应，缺失范围已明确。缺失无法恢复时记录缺证及其影响，不把无限搜索当作必需完整性。

### 3. 先建问题时间线，再决定阅读范围

先用协作记录定位决定、声称结果与候选版本，再读相关原生动作和反馈。每条重要结论记下：观察、当时解释、实际动作、后果、竞争解释、后续是否修复。全量审查可以先建立这张导航，再把尚未覆盖的会话补齐；定向诊断不必补齐无关部分。

升级条件：同一问题跨角色传播、检查结果来自别的树或运行条件、通知可能晚到、前后说法冲突，就跨会话追链。停止扩读的条件是传播与最终状态已经闭环，而不是看到第一处支持结论的片段。

### 4. 稳定呈现，再并行阅读

固定一种保留原生行号的阅读视图，按有界段输出。精确重复保留引用，机械内容注明省略范围；工具显示截断必须补读。可委派互不重叠的会话组或独立因果问题，给出唯一写目录、当前已知结论、反馈触发点及返回格式。子审负责局部阅读，主审保留跨链判断与总账整合。

有高影响确定发现就即时回传，但不要为每个猜测中断主线。没有独立有用工作可并行时不派子代理；容量不足时继续已授权的本地分析，不反复轮询槽位。

### 5. 针对因果和终态核验，随后对照当前修复

对高影响结论核对具体运行身份、时间顺序、PID或数据路径、commit/tree、真实退出码。优先寻找能否定自己的证据；区分静态可达路径、历史运行实证、最终状态与隐藏评分关联。然后核对当前修复覆盖的是机制、方法还是产品行为，避免把旧缺陷当作当前源码缺陷，也避免以“已有指引”宣称效果已发生。

升级条件：无法区分两种解释且会改变后续修复，应提出最小缺失事实或获授权验证；不能用更大范围摘要堆积代替判别。没有动态授权时，止于明确的静态结论和验证边界。

### 6. 在交付前只做一次收敛核对

核对总账与子单元SID/记录数、未读集合、缺证、最终结论及修复状态。当前报告只保留决策所需结论和证据入口，过程断点留在账本或明确标为历史。成本同时给规模和不能归因的部分，不估算无依据的收益。

完整审查的结束条件：授权范围内全部可得单元完成语义阅读，所有显示截断已补或明确不可恢复，省略有登记，最终状态与早期缺陷分开，缺证不再假装待办，三份入口一致且已主动通知主线。定向诊断则以第一阶段的决策完成为结束，不自动膨胀为全量审计。

## 最值得先沉淀的改进

优先沉淀三个简短约定：单一覆盖账本、每条重要发现的因果与反证字段、结束时的终态及修复状态核对。渲染工具只需支持稳定原生定位、有界输出和精确重复引用，不宜先造一个新的通用审计平台。若以后多次重复遇到同一手工步骤，再根据真实返工证据提取工具。

本次最大可复用收益是“将覆盖承诺与问题诊断分开”：全量审查回答有没有漏读，因果审查回答哪些证据足以改变决定，两者都重要，但不应每轮默认同时做到最大范围。
