# C1归档增量独立复核

结论：当前增量覆盖C1已定位的正常路径，未发现需再改的确定阻断。它让根原文定位和子归档共同按父身份消费当前/历史清单，避免只修children遍历却仍用错误的根路径。这里只作源码因果复核，实际归档行为仍未验收，不涉及其它正在修改的生命周期或合并代码。

读取基线：`scripts/core.py` SHA-256 `9b9ecdd0fc35b9d3dd286e0a8aef917610289ddb632212917f375c8d9d3d5780`；另读 `cells/session-archive-c1.md`、observer现有父索引写入/恢复及canonicalParentFile、Braid记录native_session_id/path的接口。未运行归档函数、测试、探针、构建或实验，只写本文件。

| 边界 | 本轮直接核对及判断 |
| --- | --- |
| 同home父A有子任务，当前活动父B | `_pi_session_tree`先读当前B，父身份不符时继续读取按A原生ID命名的历史清单。`archive_pi_children`不再先复制B清单然后失败；只复制选择成功的A清单，再沿A的connected身份链遍历children。C1机制缺口已直接消除。 |
| 当前清单与历史清单都属于A | 当前优先。observer同父恢复会先加载已有子项，A恢复后的新增事件写活动清单；再次离开才覆盖A历史。因此正常生产顺序下活动清单包含当前A的较新状态，优先当前成立，无需再按文件时间猜测或合并父。 |
| 当前清单缺失 | 尝试声明父ID的历史文件；有匹配即使用。两者都不存在返回None并记unknown，不把缺少辅助索引当应用失败。 |
| 有清单但都属于其它父 | 明确报“当前及历史session-tree均不匹配”；外层保留根原文并把observer诊断记partial/error，不静默接到其它父。 |
| canonical根原文定位 | `root_source`与children共用选择函数；正常新格式row由Braid factory保存原生UUID及path，因此历史A清单的canonical parent_session_file在读header前即可恢复。后续仍核对root header与row身份，子header与child_session_id逐条匹配。只加入历史children读取而漏掉canonical消费者的问题没有保留。 |
| legacy路径型session_id | 原文路径仍参与当前清单身份匹配，但含斜杠/反斜杠的值不生成历史候选文件名，避免把整条路径编码成伪父ID。若仍有可读根文件，其header得到的实际native_id会加入children选择集合，可定位UUID历史。没有凭路径猜一个新的原生父身份。 |
| 路径与重复记录 | 当前/历史清单及原文仍经过run内路径解析；children仍需连通父链、核对header；copy_one继续按provider/native ID核对来源及摘要冲突。增量不转移工作项归属，不合并不同父清单。 |

保留的限制如下，均不升级为这次已发生的运行失败。

1. 当前清单即使属于其它父，若JSON损坏或children结构无效，选择函数仍先报错，不继续绕过损坏去尝试历史。外层会留下诊断，根原文尽量保留。正常observer原子写入及已有严格索引校验不要求新增吞错兼容；本次没有证明存在必须绕过这种损坏的运行前提。
2. legacy记录若既无原生UUID，又没有可读且属于原父的原文，只靠复用home下的路径字符串无法确定历史父。新代码不扫描并猜配全部历史索引，这是正确的证据限制；不能宣称能补回所有旧不完整归档。
3. 当前优先依赖同一个home遵守现有observer的加载、原子覆写顺序；人工把活动清单回滚到更旧内容或多个无关进程同时写home不在本次已证使用前提内。没有为此增加锁、时间戳仲裁或另一份索引。
4. 本次只修已登记父的索引选择，没有扩大为发现所有未登记父、恢复缺失child原文或证明模型采用结果。只有真实父切换后的正式manifest包含正确A/B身份及各自产物，才构成归档行为证据。
