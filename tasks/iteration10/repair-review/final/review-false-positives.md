# 最终复审的假阳性与修复返工核查

结论：现有证据不支持把F1、FF1、FR1、FR2、C1整体撤回为误报；它们有具体接口或持久化义务，也有有界反例。应缩减的是F2的产品缺口定性，以及将F3/F5观察项累计为确定故障的做法。最清楚的实际返工链是F1修复引入FF1、历史索引新增后漏改归档消费者C1、FR2早分支修复漏掉显式head条件，以及原生屏障初稿把残留结果文件误当未交付。这说明修复需要先收敛边界和消费者，不能说明最初问题都是假的。

本核查独立于方法产品报告。逐项读原审查主张、实施记录、相关当前源码/补丁及锁定Pi接口；不改旧报告、源码或原始证据，不运行测试、探针、应用、模型或实验，不提交。主线负责按北京时间2026-09-28 23:00以来会话建立状况树；本文只判断其指定F/FF/FR/C及方法主张，不冒称完成该时段所有消息覆盖。

判别标准：源码可达反例可证明接口契约缺陷，不必等待用户再次遭遇；但它不能单独证明历史事件由此造成，也不能证明值得新增某个产品义务。已知消费者被遗漏是修复不完整，不因首次补丁被独立复核便成为产品需求。能力有取舍时，必须检查原目标是否保留，而不是把删功能自动称作根治。

## 能力削弱是否被包装成修复

**历史结果/service被动保存：当前可接受，但必须保留真实代价。** 原始R11问题是父不知道已有写任务，而非所有历史执行都必须由新父收养。F2/FF2撤掉“关闭后一定唤醒”的隐含义务合理；FR1再撤掉“只要进程活着就自行采样”，符合调用身份边界。索引、结果和下一合法输入消费仍在，当前父需要旧结果时应在有效回合查询/等待，不能先宣告完成再靠不保证的未来通知。

但`triggerTurn:false`在运行中也只是将消息暂存到本轮末尾，不是立即steer。它确实削弱了某些及时处理能力，不宜仅称“保持通知，只修安全性”。如果用户目标包含闲置期间自动处理历史完成或service失败，就需要合法输入桥或其它明确调用入口；现有依据没有该义务，不能自行增加桥，也不能把未来需要否认为不合理。本核查支持当前被动历史取舍，不支持把它说成所有异步结果都保证闭环。

**当前父有限任务不应被一并降为被动。** 原生架构报告明确保留自动收尾：有限执行终止、必要结果进入父队列、父续轮结束，再settled。把所有true改false虽然更短，会让auto-drain静默完成而父未解释结果，改变已选行为；当前最终补丁没有采取这一捷径。因此新增结果排空本身不是无必要协议，而是对既有自动收尾语义的补齐。

**旧writer守卫不应撤掉。** Sheet349原生L33–55和L137/144–159已有有限job→completed→迟到采样→writer拒绝及直接改DB的真实链。守卫正确拒绝失效调用；问题在采样发生得太晚。取消守卫或重开旧turn会掩盖错误，还允许无合法输入的工具/文件副作用，并不能用“LLM语义权威”合理化。

## 后续原生屏障审查：哪些是必要边界，哪些是补丁自造问题

`cells/lifecycle-architecture/report.md`的A/B有与具体接口相连的前提：headless auto-drain只等执行，notifier另有batch/window；Pi扩展runner捕获agent_end错误继续，而session最终仍settled。当前Pi缓存源码直接确认捕获异常和空闲triggerTurn采样的行为。它们证明的是允许的时序，不是新旧运行发生率。既要保留有限自动follow-up，又要关闭后无自发采样，必须在同一原生调用边界处理执行、通知和异常；逐个缩短delay或关batch不能完整替代。

| 后续项 | 判断与应保留的界限 |
| --- | --- |
| 通知排空与调用关闭 | **保留。** 结果持久化不等于父已接受；当前patch直接处理当前completion owner的结果并等待已在处理的Promise，沿用现有队列。无需Braid管理子任务表。它是条件性机制风险修复，不能从Sheet349直接推出pi-subagents此窗口曾发生。 |
| agent_end异常应投影失败并禁止自动续采 | **保留。** 原生捕获扩展异常而最后assistant可能stop，确有“屏障失败被当正常结束”的契约缺口。具体错误需保留；不应泛化为所有extension_error都证明业务失败。当前改动限定agent_end。 |
| 取消在屏障期间发生后仍可能continue | **保留有界回归防护。** 扩大agent_end等待后，旧abort可能先结束而新completion排队，continue重新采样；记住本次调用取消并投影interrupted符合现有取消意图。历史发生率未证，不写成旧两题取消失效已复现。 |
| 残留result文件被当未交付 | **明确属于补丁自造的假失败条件。** watcher可已接受通知、仅标记/observer/清理失败；文件存在不足以证明未接受。初稿屏障把其转failure会制造错误终态。后续accepted payload或持久delivered标记修正值得保留，不能当作新发现的旧运行根因。 |

最后一项是**实现会产生假阳性错误**，不同于**reviewer误报缺陷**。本轮区分这两个词义：独立复核指出初稿的错误失败条件是有效发现，而不是它自己在制造假阳性。新增补丁越多并不天然越安全；判断标准是每条状态是否对应真实执行/接受/取消事实，是否出现两个竞争权威。当前patch保留的是该调用的原生边界，没有理由仅因新增变量/映射就全部删除；也没有运行证据足以宣布整体时序已验。

独立核查源码：`harness/npm/patches/pi-coding-agent-0.85.1-braid-boundary.patch`、`pi-subagents-0.56.0-completion-boundary.patch`；锁定Pi 0.85.1的`agent-session.js`、`extensions/runner.js`、`agent-session-runtime.js`和`rpc-mode.js`；Braid `provider/pi.rs::start_session`、`objects.rs::apply_merge`；当前observer父索引/通知；`scripts/core.py`两归档消费者。followup中的编译/应用记录只作为实现方反馈，未冒充本次执行。

## 方法类误报与重复审查成本

方法审查的主要风险不是发现了不存在的具体bug，而是把“合理增强”“用户选择”“因果证据”合成一个“根因已修”的清单。

- R04/R05不是一般缺原文：GitHub L23已经读懂冲突；追加更多引用不能独自解决权威反转。当前product规则针对正确问题，保留；撤回“完整转交即解决”的充分性说法。
- R06/M01不是缺少契约：用途变了、旧豁免和双策略仍存；documentation有价值，但不等于已修真实调用链。保留组合方法，不将恢复文档系统当已证失分根因。
- R07/A04不是漏读vision：父L27/L46已经消费，错在用另一属性PASS排除反证。保留同属性结果解释；分类读图是用户选择，不给它额外归因。
- R08根基础责任、Issue/PR分工和A06技术栈均有用户授权；它们不是由旧得分唯一推出来的必要修法。不能为了“少做”擅自撤回，也不能因已实施而声称历史原因确立。
- M02–M04示例、金字塔、规划是表达/能力增强；没有“缺图/缺案例导致旧失败”的直接证据。保留其用途，不把它们累计为已经治愈的故障。
- 本轮提出packet文件与Issue/PR状态可能双写，只是文字歧义，未证真实双写/漂移；不应升级成新P级缺陷，更不能据此删除用户明确要求的packet能力。建议澄清单一权威与链接足够，不重开方法重构。

此前从41/44目录项覆盖到多次“无新增阻断”，并没有给出同等深度的整体根因验收。`methods-completeness.md`与`runtime-completeness.md`随后自己承认旧snapshot漏support输入、差分身份不足和继承内容未全审。把这种局部静态结论对外当整个迭代最终复审完成，是**完成度夸大**，不是每条局部缺陷都误报；目录反查发现C1有实际增益，不应把所有后续补读一概称浪费。

有证据的冗余是多次复述同一采用/效果未知、重复目录对账仍未回答原问题，以及把未变化的条件观察再次作为“下一次最终审查”。有证据的增益是FF1、C1、FR2显式head条件与原生接受/取消边界。没有逐次审查耗时/完整消息时间树，本文不编造可节省分钟或误报率。
