## 执行缺口与关闭条件

截至本轮所读版本，lab/arc_bench/execution.py 的 assemble 将 --route 冻结到 inputs/gateway-routes.json 并传给 variant builder；I14-dx-test/build.py 与 pi-minimal-vv-dx-test/build.py 只复制该文件。后者 main.py 读取 private-models.json 或注入的 OPENAI/FACTORY26 端点，没有读取路由。I14 的实际模型绑定也由原生配置/注入消费，本轮未找到包内路由启动网关的路径。因此 source input、packaged file 和 actual model route 尚未闭环。

修复应由执行链的持续负责人完成：在模型进程启动前消费公共 catalog、选定有序路由和相应私有凭据；将实际网关绑定注入所选 variant，并保持明确的网关生命周期、真实路由回执和原始错误。ARC API、比赛沿各自明确端点或平台注入消费，不能因 --competition 或候选目录自动改成自费链；不要求新增统一配置语言。角色模型参数和原生接续语义保持本次既定合同。

关闭需要实际运行记录证明所选链被消费，角色请求未意外落到 catalog 默认或 target 的 ARC 默认，实际 fallback 与冻结顺序一致，三类调用配方与提交身份可分别取证。不得用模拟请求或新增设施测试替代实际反馈。新执行链及真实模型验收已由[设施任务](../finals-experiment-loop/packet.md)持有，本侧不得接管其运行或擅改在途执行版本。
