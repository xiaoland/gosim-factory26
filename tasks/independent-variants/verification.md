# 验收方案（待复核）

目标是证明四份 Harness 独立、迁移未意外改变原生能力输入、官方交付和诊断可用。
不以代码行数、配置文件消失或单元测试数量证明目标成立。

| 主张 | 最小检查与证据 | 不证明什么 |
| --- | --- | --- |
| 单个 variant 可独立执行 | 在临时目录只放该 variant、明确依赖和普通支持模块；无其他 variant、旧 resolver/materializer 或完整 harness，执行包入口。四份均检查。 | 不要求复制上游依赖源码；也不等于模型能完成全部赛题。 |
| 改动不会传播给其他 variant | 用临时副本只改 mixed 的一段指令及局部执行行为，重新装包；其他三个源码与载荷材料保持相同，输入列表不引用 mixed。 | 不拿 ZIP 容器元数据或临时路径差异当行为变化。 |
| 保留既有实验条件 | 比较迁移前预演基线与迁移后实际传入 Pi/Braid 的模型、reasoning、assignee/defaults、指令、角色 tools/skills、context 设置；只归一化明确的绝对路径和新文件布局。 | 不能将有效配置相同推导为随机生成结果或分数相同。 |
| 官方入口与交付有效 | 复用已有 Linux smoke，四份入口均验证成功交付、失败非零退出、平台文件保留；共用 runtime 只检查一次真实工具启动。 | 无模型 fake 仅替代生成结果，不用来模拟 Pi/Braid 协作正确性。 |
| 错误和会话可定位 | 使用既有小型原生会话 fixture 验证 `show --run`、feedback、development analysis；对迁移后真实运行再核对根/子会话、原始模型错误及 Braid 对象关联。 | 不为 SVC Corpus 的路径、篇目或措辞写断言，不修复独立任务中的全部 viewer 发现缺口。 |
| 依赖重用 | 同 runtime 输入下再次构建只改指令的包，确认复用 npm/浏览器/Rust 构建层；不重复安装 Runner。 | 不新增缓存框架或性能基准项目。 |

先做现有真实物化接口的无模型预演，保存输入基线。
实施后沿用现有测试入口，删改旧 DSL 测试，新增的检查只覆盖上述独立性和实际交付边界。
真实模型接线优先用迁移后的 mixed 跑一个小任务，并明确触发一个原生子代理；成功后才扩展到其余配方和既定评分安排。
真实调用需要接线/实验授权及可用模型服务；当前不发起模型调用，也不以旧额度错误断言服务现在仍不可用。

本任务不自行扩大 bench 矩阵。
完整评分仍沿用既定方法，等待用户通知设施就绪并对齐 SVC Corpus 尚未完成的验收；无模型验收完成不关闭该任务。
