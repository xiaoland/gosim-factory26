# 独立 Variant 诊断证据合同（事实采集）

范围限定为现有消费者的只读事实。以下结论来自指定脚本、相关测试 fixture 和现有归档索引入口；没有运行模型、bench 或 rollout。

| 消费者 / 入口 | 必需材料（实际读取） | 可选材料（存在时读取） | 是否依赖 effective profiles | 建议保留接口 |
| --- | --- | --- | --- | --- |
| `scripts/run_viewer.py:build` → `local_run` → `inspect_runs.list_runs/_summary` | `runs/*/run.json`；`config.json`（用于 backend/task、旧 variant 推导和 benchmark revision）；目录名作为 run ID | `evaluation/*/summary.json`、`application-hashes.json`、`analysis/*/overview.json`、`native/manifest.json`/会话 JSONL、评测结果与日志、`feedback.json` | 否。`inspect_runs._summary` 只读取 `config.json` 的普通字段；`run_viewer.local_run/native_process` 消费会话清单、原生事件和评测证据 | 保留 `run.json` + `config.json` + `evaluation/<id>/summary.json` + `native/manifest.json` 的归档布局；variant 可直接来自 `run.json.variant`，旧归档才由 backend/workflow/svc 推导 |
| `scripts/run_viewer.py:hosted_runs/platform_run` | `runs/competition/**/hosted/*/inputs.json`、同目录 `state.json`；`state.tasks[task]` 至少需 `run_id`，并使用 `remote_status`/`phase`/`platform_result` | `tasks/<task>/status.json`（`value.id`、`requirement_id`、`status`、`tests`、计数、`failure_reason`、时间）；logs、traceability、commit-history、official stdout | 否。variant 只从 `inputs.json.variant` 或 hosted 目录名展示 | 保留 `inputs.json`/`state.json` 身份与 `tasks/<task>/status.json` 关系；平台结果至少保留 run ID、任务、状态、阶段、计数/score、tests、failure_reason、runner events |
| `scripts/run_viewer.py:playground_runs` | `runs/playground/*/status.json`，且 `value.id == 目录名` | `observation.json`、traceability/commit-history、logs、`tests` | 否。展示字段来自平台 status | 保留 `status.json` 的 id/status/requirement_id 或 display_name、计数/score/tests；保留 logs/observation 为证据入口 |
| `scripts/run_feedback.py:collect` / `brief` / `watch` | `run.json`；生命周期优先读取 `outcome.json`，并读取 `interruption.json`；根目录 `pi-events.jsonl`/`codex-events.jsonl`（若有） | `native/manifest.json` 及其中声明的原生 JSONL；Braid 旧路径 `run.json.runtime.work/braid_state/sessions.json`；`analysis/*/overview.json`；写出 `feedback.json` | 不读取 effective profile 内容。`native_summary` 仅报告 manifest entry 的 `profile_id`；`run.json` 的 variant/backend/task 作为摘要身份 | 保留 `run.json` lifecycle/status/phase/variant/backend/task/failed_phase/error；`outcome.json` 的 status/stage/error/analysis/evaluation_id；声明式 `native/manifest.json` + sha256 + provider/native；原生事件文件 |
| `scripts/factory.py:analyze` | `run/run.json`（backend 仅用于无 manifest fallback）；原生会话：优先 `native/manifest.json` 中每个 entry 的 `native`、`provider`，且不能有 archive_error/缺失 native；无 manifest 时扫描 `native/*.jsonl` 或 `pi-session.jsonl` | manifest entry 的 sha256 与身份字段：`native_id`、`profile_id`、`effective_profile_digest`、`parent_native_session_id`、`native_role`、`work_item_kind/id`、`assignment_generation`；SVC source 或开发 `.venv/bin/svc`；缓存 `analysis/<index>-<fingerprint>/` 下 `evidence-v4.zip`、`export.json`、`overview.json`、`profile.json`、`provenance.json` | 不需要 effective profile 对象；`effective_profile_digest` 等字段被复制进 analysis provenance 的 `session_identity`，用于缓存 fingerprint/身份说明，不参与 SVC 查询内容 | 保留原生 manifest 的 session identity（尤其 provider/native/sha256 和上述可选身份字段）以及 `factory.py analyze(run, svc_source)`；保留 analysis provenance/缓存按原生字节和 exporter provenance 去重 |

| `scripts/official_matrix.py:freeze`（历史 hosted 矩阵入口） | 每个 ZIP 内 `package-manifest.json.capabilities.variant`；`variants/factory/config.json.effective.variant`、`effective.profiles[*].roles[*]`，并要求恰好一个 visual model；四个 ZIP | 生成后的 matrix manifest 中 `package_sha256`、`model_config`；`execute` 消费冻结 manifest、ZIP hash、competition/tasks | 是，且是唯一在本次核实中直接读取 effective profiles 的消费者：只取 variant、一致性和 visual role model；其余 routing 字段来自 `config.json` 顶层 `base_url/model` | 若历史 freeze 仍服务新提交，保留 ZIP 内 config/effective 的兼容入口，或在显式提交元数据中提供等价的 variant/base_url/model/visual_model；不能让 viewer/feedback/analyze 依赖整棵 effective profile |

## 交叉核实与边界

- `tests/test_run_viewer.py` 的小型 runs 索引 fixture 同时确认了 Factory、Competition、Playground 三种发现入口；`build()` 通过 `runs/*/run.json`、`competition/**/hosted/*/inputs.json`、`playground/*/status.json` 聚合，而不会扫描任意新 run 布局。
- `tests/test_run_feedback.py` 的 fixture 确认了 `run.json` 状态优先级、`outcome.json`、`interruption.json`、声明式 `native/manifest.json`、Pi/Codex 事件文件和 `feedback.json` 的入口。未声明且位于其他路径的事件不会被采集。
- `tests/test_factory.py:test_analysis_source_change_reexports_without_overwriting` 确认 `analyze` 以原生会话字节哈希、provider 和 SVC exporter provenance 形成缓存；SVC 源变化或会话字节变化生成新缓存，旧缓存不覆盖。
- `tests/test_local_experiment.py` 的 driver fixture 确认 local facility 只要求 `experiment-result.json` 的 schema/status/summary、artifact 路径和 OTLP 原始 batch；同一 competition 下不同 variant 的证据按独立 run 目录隔离。
- 未确认：独立 variant 迁移后是否仍需让新 ZIP 提供 `variants/factory/config.json` 这一历史路径；这里只能确认 `official_matrix.freeze` 当前硬编码读取它。也未确认任何新消费者会读取 `effective-config.json`；上述入口均未读取该文件。
