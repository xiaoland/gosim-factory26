## 对方法候选的约束

1. **提示/Skill：给稳定内容与瞬时状态各一个职责。** description 保留当前范围/约束/待决/责任与精确证据入口；packet 保存任务决定和实现计划；共享文档保存被下游消费的契约。正文中的 head 只记录冻结候选与证据适用范围，活跃提交直接指 `headRefOid`。依据是 16:33 的成功调整、PR21 指针链与 `60635798` 的循环，不是字数统计。
2. **提示/Skill：排除必须有被接受的承接。** 声称“属另一阶段”的工作须链接具体 obligation/负责人/接收回执；若原需求覆盖两个对象，不能用 REQ 编号前缀当 ownership 完结依据。#305→#308→PR22→#332 支持这条候选；无需增加所有文档的复制量。
3. **提示/Skill + runtime：明确内容修正和关闭单位。** 可解析历史引用允许 redirect/下次必要变更批修；只有实际误导/阻断消费才即时工作项。resolve 前核实整个 thread 的未决与消费状态，确认稳定结论已提升且依赖已承接。历史运行的 CLI 反馈不足是本例支持的 runtime 候选；当前 Braid 已有相关返回结构改动，不能重复建议“从零增加”，须按已存在实现验收。
4. **提示/Skill：以变更影响确定证据是否失效。** 同树或纯证据文档变化应允许引用旧运行，注明差分与边界；新运行只因尚未覆盖的变化/失败触发。把有限实测和普遍证明明确分开。PR19 merge、PR20 #299 的成功复用与 PR22 重跑形成同一 lineage 内对照。

这些候选不保证提高分数。无额度验证可用本次只读材料做人工桌面推演：按原时间给下一接手人入口，检查能否找到有效契约/未决/承接人；用已留存正文变更与 thread 结构检查 lifecycle 规则会允许/阻止哪些具体动作；比较旧/新提示是否明确消除 PR21 决策摇摆、#308 无承接排除、#324 粒度误判和证据循环。**不调用模型试跑，不改 variant，不运行应用或 Harness 测试。**
