## 关键技术决定（含证据）
- **SQLite 驱动锁定 `better-sqlite3@12.6.2`（精确版本）**。实测：`13.0.3` 的 engines 为
  `node >= 22`，在交付环境 Node 20.19.3 下 `new Database()` 直接段错误（SIGSEGV）；`12.6.2`
  在 Node 20.19.3（`/usr/local/bin/npm` 安装）与 Node 24.10.0 下都能安装、加载、读写。
  原生模块的 ABI 与"安装时的 Node 版本"绑定，**同一 `node_modules` 跨 Node 版本复用会失效**，
  因此平台核验必须用 `PATH=/usr/local/bin:$PATH` 重新安装。
- **后端发布形态为源码直跑**：`npm run start` → `node src/index.js`。后端不依赖安装期编译，
  即使平台以 `--omit=dev` 安装也能启动；类型安全通过 `npm run typecheck`
  （`tsc --checkJs`，JSDoc 引用 `shared/types.d.ts`）在开发期保证。
- **前端构建包含 `tsc --noEmit`**，类型错误在平台构建阶段即暴露。
- 网格**不虚拟化**：整个工作表都在 DOM 中，使选区外单元格同样暴露 `aria-selected="false"`
  （契约 §3 的精确断言要求）。事件委托 + `React.memo` 保证切换选区时只有翻转状态的单元格重新渲染。
  默认结构为 **6 行 × 26 列（A–Z）**（共享契约 v1.2 = Issue #1 comment #15，修订 v1.1 = comment #12 第 6 条的 9 行）：
  Playwright 的 `getByRole(name)` 是**不区分大小写的子串匹配**，行数 ≥10 时 `A1` 会被 `A10`/`A100` 同时命中，按可访问
  名称定位单元格的验收断言会 strict mode 失败（已实测：1000 行时 `getByRole('gridcell', {name:'A1'})`
  命中 112 个元素 = `A1` 本身 + `A10`–`A19` + `A100`–`A199` + `A1000`）。需求引用的坐标最大行号为 6（`A5:C6`）
  且需求未规定初始维度；插入行是需求明示的结构操作，若外部 harness 用朴素定位且与其参考实现自洽，其初始行数须落在
  [6, 9]，取 6 对这类 harness 全部存活（容忍最多 3 次净插入），取 9 在插入 1 行后即不相容。列保持 26：`A–Z` 在 ≤26 列时
  无子串歧义悬崖（`AA` 从 27 列才开始），预防性取大在列维度没有歧义代价。`e2e/smoke.spec.ts` 既对种子范围 `A1:C6`
  的每个坐标断言朴素定位唯一，也断言结构总量精确（6 个 rowheader、26 个 columnheader），默认结构向上或向下漂移都会失败。
  配套纪律（同 comment #12）：结构操作把工作表扩到 10 行以上后，验收脚本定位 gridcell 必须用
  `exact: true` 或 `[aria-label="A1"]`。行列数只由结构操作（子 Issue B）与 CSV 导入（子 Issue A）改变。
- 首页与编辑器共用 `updatedAt` 与同一格式化函数（`frontend/src/lib/format.ts`）。
- **选区与切换工作表不更新 `updatedAt`**：它们不改变工作簿内容，若更新会导致"首页与编辑器
  的 Last updated 值不一致"。内容类变更（单元格、整表状态导入、重命名、创建）都会更新。
## 约定（消费方必须遵循）
- `row` / `col` 一律 **0 基**；`A1 = {row:0, col:0}`。API 与数据库一致。
- 单元格 `raw` 是用户提交的原文；公式以 `=` 开头**原样存储**，不存计算结果。`raw === ''` 表示清空。
- 错误统一为 `{error:{code,message}}`；文案使用需求规定的英文（如 `Workbook name cannot be empty`）。
- 每工作表显式持久化 `row_count` / `col_count`（默认 6 × 26），渲染与结构操作都读这两个字段；
  基础层只做“越界即 400”，不隐式改变结构。
- 选择矩形持久化为 `{r1,c1,r2,c2,anchor}`，仅在 mouseup（确认）时写库；切换工作表不覆盖其他表的选区。
- 迁移与种子可重复执行；种子只补缺失、绝不覆盖已有数据；**不提供重置端点**。
