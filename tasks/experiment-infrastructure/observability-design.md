# 自包含运行诊断与耗时剖析

状态：2026-09-28 用户复核并授权实施，进展见 cells/self-contained-observability.md。依据 [现有接线盘点](observability-inventory.md) 与 [本轮总目标](../braid-product-hardening/iteration.md)。
目标是回答一次运行为什么耗时、为什么失败、哪些模型和协作行为消耗了 token，并能从结论回到原始证据。

## 采集与存储

复用已有 lab/otlp.py、SQLite 和 Braid viewer，先不引入第二套可观测性平台。
把接收器从实验控制器的临时生命周期中分离，提供可单独启动的接收入口和持久化运行注册。
每次官网或 WSL 执行优先在执行环境本地持久化，生成阶段结束后停止接收并将数据库放入既有证据归档。
官网和 WSL 使用相同数据格式、查询和展示；不要求 ARC traceability 保存或解释数据。

```text
Braid 调度事件 / Pi 请求与工具事件 / 原生 usage / PBB 进程记录
                    ↓ OTLP
执行环境内 Collector → SQLite 原始批次与身份映射
                    ├─ 既有工作区证据归档 → 本地查询与静态诊断页
                    └─ 可选传输 → 自管接收端 → 同一查询与诊断页
```

本地持久化是基本路径，联网传输只改善实时性，失败不丢本地诊断材料、不阻断 Agent。
官网仍需平台下载工作区或独立出站通路来取得数据；独立于 ARC traceability 不等于独立于平台的文件传输和网络限制。
公网实时接收所需的可达地址尚未确定；先不承诺官网实时推流已可用。
包内接收器的最小依赖、端口分配、异常结束时 SQLite 归档方式在实施准备中核实；接收端不能使用应用评测端口。

## 观测边界

身份由执行宿主记录实验/run/attempt，Braid 记录工作项、成员、逻辑会话与物理会话，原生扩展记录内部子会话和调用。
内部 ID 可以用于关联，LLM 不承担填表、埋点、计费或 trace 关联任务。
不向生成应用加入代码，不让模型为了可观测性改变回复格式。

Pi 0.85.1 的实际类型定义已确认 before_provider_request、after_provider_response、message_update/end、tool_execution_start/end 存在。
after_provider_response 发生在消费响应流之前，因此只能表示收到响应头，不能当模型生成结束。
首个可见流增量、最终 assistant message 与 usage 分开记录；TTFT 不能冒称服务端排队或推理耗时。
重试、取消和中断留下未完成状态，不能补造结束时间；具体重试回调顺序仍在实施准备核实。

| 问题 | 数据口径 |
| --- | --- |
| 谁消耗 token | 原生 assistant usage 按消息身份去重，按模型、成员、工作项和子会话聚合；输入、输出、缓存、推理字段保留来源及缺失率 |
| 花了多少钱 | 官方账单聚合与冻结价格估算分列；原生 usage 与平台官网合计的差异可见，不强行对平 |
| 模型慢还是工具慢 | 请求发出、响应头、首个流增量、消息结束；工具调用开始/结束；PBB 后台 job 实际起止独立展示 |
| 结果出来后为何未推进 | 结果产生、通知投递、会话消费的实际关联；只有能关联时才计算等待，不能用任意消息间隔推断 |
| 协作为何昂贵 | context reset 原因、追加/改写、通知收件与实际唤醒、重复恢复及空输入次数；保留可回溯实例 |
| 并行是否有效 | 总墙钟与活动区间并集、各资源累计时长分别显示；重叠时长不相加冒充总耗时 |

复用现有证据解码和父子会话清单，不同时维护另一份不可核对的统计。
原生 usage 的累计 gauge 不跨采样相加；无法确认的子会话和指标标为缺失。
历史运行只能重新汇总已有 token 和已证实时间窗；新采集字段不能追溯补造。

## 使用入口与验收

从实验目录直接进入概览：运行阶段、token/费用、模型与工具时间、协作开销、证据覆盖与明确缺口。
按工作项或成员下钻到时间线，再到具体调用、进程日志和原生消息；保留机器可读导出供分析 Agent 定向取证。
仍复用现有 viewer，不建立另一个长期运维的 dashboard 服务。

在用户批准实施范围后：先拆出并接线接收器，再补原生边界采集，最后整合查询和视图。
使用已授权的真实 WSL 两题检验数据是否随运行连续写入、异常信息是否保留、token 是否能回溯到 usage、时间是否存在误加和缺口。
官网接线需后续获授权的真实运行验证；当前冻结恢复包不加入新采集代码，不为设施验收另开收费实验。
不新增 Factory 或开发设施测试；验收记录来自真实操作和实际运行材料。
完成标准不是页面有图，而是从一次具体停滞或失败能直接查到工作项、会话、调用和原始依据，且不再手工拼接多套 ID。
