## 公共契约先确定

公共契约只定义实际需要连接的事实，不建立通用插件、工作流或 Agent 语义框架。

1. `manifest.json` 固定实验、job、输入引用、argv、可选结果路径、已声明资源处理命令及比较意图。v1 读入时补其默认结果路径；新 v2 的标签、文件输入与结果文件可选。计划请求和冻结进度单独保存，最终清单发布后不改写。
2. `run.json` 使用 `record_type=lab.run`、schema v2，保存 experiment/job/attempt 序号、retry_of、触发操作和控制器引用。执行状态、进程退出、结果契约、采集和清理分别表达。沿用一个 run ID 表示一次尝试，不再生成同义 ID。
3. 精确引用可从文件/目录读取；experiment/job/run/制品引用携带所属根和身份，机器来源另存。模糊名称不唯一时返回候选。旧 `--runs-root` 使用技术方案中的 `.experiments/<id>` 旁置布局；新 `--experiment-root` 使用标准目录。两者共用加载及查询逻辑。
4. 发布声明包含生产者、实际产物位置、内容身份算法/清单及来源输入；设施事件只引用声明。产物索引可重建。容器内文件位置由 ARC 的已知 bind 映射，不能直接使用宿主绝对路径。
5. 资源处理命令在冻结计划内声明。资源事件只选择已声明处理者并提供具体资源事实；inspect 只观察，cleanup 才改变资源。输入为明确的 run/资源声明，输出为带证据的状态。不得执行事件中临时给出的命令。
6. 操作文件分别保存 CLI 请求、控制器受理/分配和回执；操作 ID 不等同 run ID。控制器通知游标包括世代和序号，通知引用原生产者事件；分析引用实际输入清单、batch 截止点及解释器身份。

新文件 SHA256 只含 bytes；目录清单按相对路径排序，记录条目类型、文件内容摘要及执行位。软链接记录链接目标，不跟随到快照之外；遇到设备/FIFO 等非应用文件明确报错。快照复制实际文件，不能用可共同修改的硬链接冒充冻结。ARC 的纳入/排除规则只有一份 helper，并在身份中标明规则版本；历史算法只读保留。

## B：共享计划与可靠执行

将 `lab/run.py` 中的 snapshot/prepare 拆到 `lab/plan.py`。按解析后来源复用实验内快照，以 staging 目录发布完整输入；保留 `run/inputs/<name>` 的旧路径形状，用相对链接连到共享内容。输入写保护是协作约定，不声称同一用户权限下提供安全沙箱。输入失败影响的 job 在计划中明确 preparation failed，其余就绪项可派发；没有启动的失败项不伪造执行次数。

冻结控制器的 lab 源码后，从该副本启动 controller。记录真实 Python/依赖版本、启动目录和来源哈希；启动工作目录避免当前 checkout 抢先覆盖冻结模块。CLI 查询可以用当前代码，执行与继续使用该实验固定的代码；改变执行代码应产生新条件及来源记录。

`lab/run.py` 保留调度和 Popen；`lab/control.py` 承接锁、进程身份、IPC、操作及通知。控制器单循环串行分配尝试和写入执行事实，worker 用 Queue 返回启动/退出/收集观察。每个在途尝试一个线程，按 ready/active/slot_limit 派发；不操作 ThreadPoolExecutor 私有参数。

开始工作前持久保存操作对应的 run 分配，Popen 返回后立即记录 PID/start time/pgid。进程退出后先保存退出事实，再处理结果解析、产物索引及遥测统计。单 job 错误继续其他工作；控制器无法保存必要事实时关闭派发并尽力结束所属工作。

受理 run 操作时为所选就绪 job 分配 queued 尝试，只在获得槽位后 Popen；取消 queued 有明确 run 记录。原配方 run 新建实验，已有实验引用 run 只安排从未分配过尝试的就绪项；已有尝试要再次执行必须 retry。两者不能都解释成“重放整份清单”。尝试数量与真正 started 的数量分别展示，准备失败的 job 没有虚构尝试。

SIGINT、SIGTERM 与 socket stop 转到同一控制路径。先禁止派发、取消等待项，再对所有已登记在途进程进入统一停止状态机；避免停止快照之后新加入的进程漏掉升级处理。退出未知、停止请求、实际退出、资源清理确认分别保存。默认 30 秒仅是停止宽限，不增加正常模型或实验超时。

以实验文件锁限制一个调度所有者，短私有路径放 Unix socket。后台启动日志落盘并脱离终端；受理不明只查询原操作。reconcile 读取所有权并执行已冻结的检查命令，清理只在显式操作中执行。失联不会触发模型重跑。wait 从持久通知补读后订阅；生产者文件跟踪发生在程序内，主会话不轮询心跳。

## C：OTLP 与分析入口

继续使用 `lab/otlp.py` 的 SQLite batches 与 stdlib HTTP 服务。宿主新增 `lab/requirements.txt` 声明最小协议依赖 `opentelemetry-proto`、`googleapis-common-protos`，实施安装时在独立 WSL lab 环境解析并锁定实际版本，不借用 Codex/LiteLLM runtime 的隐含依赖。仅查历史记录时不导入这些协议包。

分开只读连接与写入初始化。补采的升级事务只新增会话/元数据表，不改原批次编号与 payload；缺少新元数据的旧行保持 legacy unknown。保留旧 list_batches/read_batch 默认调用语义，新 CLI 使用有界分页、截止点和续读位置。SQLite 导出使用一致读/backup，不直接复制正在写的主文件。

HTTP 接收补 gzip 的有界解压、envelope 校验、protobuf 错误、提交后 200、可重试保存失败与接收诊断；使用 64 MiB 可配置限额，不截断内容。通用与 signal-specific exporter 配置一起处理，容器映射保留路径及三信号差异。正常关闭等待已接收写入；请求读取有明确的可配置网络空闲超时，不能让断开的上传永久阻塞控制器收尾，该超时不作用于 Agent/模型执行。

补采复用相同 receiver/backend，建立新会话/凭据；认证失败无法归属 run 时只写服务诊断。已保存正文及传输错误分开，内容不静默去重。`evidence` 的文件范围读取、批次导出和 analysis.json 查询可放入一个小型 `lab/evidence.py`，不建设索引服务。

现有 Braid viewer 继续自行调用 Braid 解码/重建，新增 analysis.json 记录来源与截止点。Factory/native 消费者只增加共同入口和结果来源，不改其会话语义。用户显式指定分析命令才能运行，读取 analysis.json 不加载代码。

## D：ARC 应用交付、资源与复评

新配方把 ARC 适配器目录作为命名输入，调用其中脚本。抽出一份 stdlib 的应用清单/复制 helper，由入口包装器、noop、replay 和打包器共同使用，相关包显式带入它；单独冻结的旧 adapter 文件仍可按原记录读取。

扩展现有 instrument_entry，保留原包于 agent/，透传 argv/stdout/stderr。原入口使用独立进程组，入口结束后按固定 Runner 的收尾语义清理该组，再复制 application 到 `/workspace/.lab-artifacts` 临时目录，原子发布清单与 receipt。宿主无需确认后才允许部署；通过已知位置读取声明并重建索引。入口退出、清理、发布各自有结果，不能让发布失败覆盖真实入口退出码。

适配器调用 Runner 前保存实际 image ID/workspace/资源意图，启动命令只用该 ID。实时读取 stdout 并保留原文，看到精确容器名后记录，取得完整 ID 与 bind 后补全资源声明。新增 inspect/cleanup 子命令供冻结 hook 调用；正常退出和失联恢复共用核对与清理实现。清理按完整 ID，且先收回本次启动进程；Docker 启动尚不确定时一次 absent 不代表确认清理。

增加 `python -m lab.arc_bench evaluate <application-ref>`，从来源或显式参数取得冻结需求、测试、coverage/selection、Runner 和镜像，生成通用计划并执行。默认沿用来源条件，缺少快照时返回具体缺项，不能选当前 checkout。改评测集或范围产生派生实验。

本地复评直接 `--template <冻结应用> --agent <核验型noop>`；noop 恢复声明的执行位并计算实际消费见证，不匹配就停止部署。不传生成 Agent 包或模型 env。结果核对场景 ID 和数量，不能只要求恰好一条测试。回放 ZIP 保留交接用途，新包恢复执行位并核验，旧包按旧规则解释。

`arc_matrix.py` 和 Hackathon matrix 改为生产 v2 清单及显式结果约定。Hackathon 配方冻结套件一次，场景 selection 独立引用它；为官方 Runner 需要的逐场景测试目录在 adapter workspace 物化，避免把整套 TS/coverage 复制 71 遍。这里不修改测试内容或应用来提高得分。

## E：模型网关的请求关联

保留 `scripts/hackathon_gateway.py` 的服务入口，新增外部命令包装模式。旧参数继续作为 serve 的兼容形式。服务的非秘密连接声明、实际 callback 源码与路由身份固定在新 state；供应商 key 和 run token 只在私有文件/环境中。

包装模式接收 service state、原 env 和调用方声明的 URL/key 变量映射。生成 run 绑定后，通过调用方指定的 `--env-file-var` 环境变量交出临时 env 路径；ARC 配方指定 `ARC_MODEL_ENV_FILE`，底层 adapter 命令不再同时传旧 --env-file。直连路径继续接受显式 --env-file；两种来源同时指定且不一致时给出明确配置错误。这样无需在 lab argv 模板内再嵌套一套花括号替换。Meter 凭据保留独立接线；通用 lab 和通用包装逻辑不识别 GATEWAY_URL 等 Harness 配置名。

基本 custom_auth 根据 token 摘要定位私有绑定，返回可信 run/binding 和每次新建的 ingress request ID。pre hook 从认证对象写入受控 metadata，记录改写前/后参数；log_pre_api_call 记录可观察的上游尝试与实际路由。Chat 和 Responses 都接流 iterator hook；逐条透传，不拼完整响应、不改变重试策略。分别记录有业务终止标记、正常 EOF 但终止未知、异常和取消；HTTP 响应开始不充当模型完成。

当前网关以一个进程服务，线程锁保证同一诊断文件追加不交错，不引入日志队列服务。生命周期记录保存原错误/状态与已观察 usage；已知 secret 字段与认证头不进入公共日志，不用全量环境或提示词辅助归属。证据写入失败写独立 stderr 并保持原模型响应；认证存储不可用则明确拒绝新请求，不能放开认证。

包装命令结束后撤销本次绑定，保留非秘密记录和已在途请求上下文。网关 inspect/cleanup 只处理已登记绑定，不停止共享服务。可选 exporter 读取持久诊断后发 OTLP并保存发送游标；失败后保留原文，下次显式补采可重发，去重语义归此生产者。
