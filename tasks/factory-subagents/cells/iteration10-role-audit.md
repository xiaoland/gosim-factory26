## 机会到采用：三个角色的实质区别

### Executor：有实际实施机会，失败主要在所有权和交接

官网三个调用的完整任务长度为 2,790、3,671、2,747 字符；Flash 为 2,527 字符。它们都给了来源、cwd、范围、检查和交付，不能把失败概括成“没有给充分上下文”，也没有输入超限/截断导致失败的证据。长任务里真正缺的是当时谁还在做这件事，以及恢复后哪个子 run 已经承担它。

### Explorer：没有执行证据，也没有已证角色阻断

四组实际 list 都能看到 explorer，当前角色具备搜索/bash、默认 fresh/只读，方法按需取本地事实或官方资料；没有 explorer 调用、工具拒绝、子失败或返回消费。因此无法从零调用区分“不知道该用”“认为不划算”与“没有足够独立工作”。不把父读过很多行直接记成浪费，也不把少量已知查找强制委派。

两种有证据的机会需要区分：

- **可独立交出但净收益未证：** Sheet 早期共享结构/公式/History 边界。#8 03:06 已列跨表引用、行列结构、验证、透视的联动，后来的跨表 undo 缺口说明“正向结构操作究竟改哪些表/字段，逆操作当前恢复哪些字段”是一个可独立调查、能返回来源和反例的事实问题。explorer 可查确切版本、调用路径与状态表，advisor 再比较责任边界；这不是要求固定先 explorer 后 advisor。早期接口尚在形成时，没有实现可查，直接让责任成员给契约可能更有效。
- **直接工作已经有效，不需要补一个角色：** 09:21:36–09:23:29，Sheet #5 在另一个 PR 检查后台运行期间，直接查看 #4 routes、formulas、现有检查和前端恢复逻辑，在隔离应用工作区构造真实反例并发 #214。根 09:24:24 的 #217 据此选择原子恢复方案。这个可观察的闭环证明调查有用，不能证明另派 explorer 会更快。动作及结果见 [undo 调查摘录](../packet.md)。

这里的重要修正是不要混淆“需要独立的信息结论”与“必须使用 explorer 这个名字”。如果未来父会话要重复吞入大量互不相关日志、API 资料，而另有独立工作可以继续，才有可观察的委派收益假设；返回应是支持一个决定的结论与最小来源，不是把同一原始材料复制回来。当前没有证据支持为 explorer 改模型、增加工具、添加自动调用阈值或硬性配额。

### Advisor：有高影响机会；已落地的前移说明需实证

六组均无执行，因而无 actual advisor model、返回或消费可归属。已有四组实际角色发现和一次实现后明确考虑咨询，否定了“所有会话完全不知道角色”的统一解释，但不证明其它会话看到全部角色方法。

高价值窗口沿用三项原始事实：Sheet 根 03:08 的 #13 将五种冲突种子解释变成全员契约；Sheet #8/#89 的跨表结构与后来的 #214 反例；GitHub Issue #8 在实现自检后才考虑 advisor 验收风险复核并继续自行验证。前两项的证据是公开评论及真实动作，最后一项的考虑只用于定位时机，不单独充当不使用的因果证明。未见 adviser 时不会虚构“返回被忽视”。

此次读取时当前父 `instructions.md`、advisor description/正文与 SVC design 的 Independent Judgment 已要求在共享解释、责任接口和仍有假设的验收判据形成前咨询；svc-sub-agents 已将咨询从普通执行/调查的成本收益门槛中分离。**这是已落地的候选修法，不是本报告的新建议，也不是历史已验收。** 不需再加同义长说明。真实验收应观察父收到建议后修改决定、做一个关键核实、或写出有理由的不采纳；角色被启动、报告更长、双方同意都不是收益。

## Advisor actual route 最快怎样核实

静态链现在可定位到：`agents/*/agents/advisor.md` 的 `factory26/kimi-k3:high` → 同 home `models.json` 的 OpenAI completions descriptor → `run.py::native_files` 注入本地 gateway base URL → `scripts/hackathon_gateway.py` 的 `kimi-k3 → KIMI`，上游模型仍为 `openai/kimi-k3`。**没有自动映射到 kimi-k2.7-code。** 09-24 曾成功的一次 K2.7 简单 Chat，只验证当时该模型的非工具调用，不能证明这条 K3 子角色路线。

迭代 10 的真实 Hackathon 验收中，最快有效验证是根在第一项真实共同前提/共享契约决定前，正常调用一次 advisor，给允许需求和一个尚未定案的问题；让它按需要读取一处原始材料并完成返回。一次真实咨询即可同时观察角色解析、fresh 子启动、Kimi 流式工具调用/回填、完成通知及父消费。无需另建一套设施 smoke，也无需为了验证制造假的产品问题；若根任务此时没有有价值问题，应继续实际工作，route 保持未验。

必须记录三个不同身份：请求的原生 provider/model、网关选定上游、返回原生实际模型；再保留 HTTP/工具/退出结果与子 UUID。成功的 `/models`、list、spawn receipt 或 HTTP 首包均不足以证明完成。当前预算代码显式排除 Pi 子角色的独立名额计算，不能把“原生子角色不是新 Braid session”倒推为旧版本调用一定放行；实际冻结版和原始错误才是依据。

若 K3 返回模型不存在/无权限，停止对同一事实盲重试，把准确错误交主线决定可用的 Kimi 模型并显式修改配方；不得暗换 K2.7 后仍记 K3 成功。若子完成而父未采用，route 可用、方法闭环未证；若建议被合理拒绝，采用链成立但收益仍需具体差异。当前本 worker 未发任何请求。

## 供主线落实的优先级

第一项应补的是 **Braid 指派已交由成员推进与 Pi 内部委派的边界**，它有直接公共行为反例，现有单纯命名提醒没有覆盖。第二项是让已落地的旧 run 身份交接及前置咨询在真实事件中完成“返回→父消费”闭环，避免为缺证再建机制。第三项是保留 executor/explorer 普通委派的收益判断：发现一个实在的不重叠工作才委派，已知查找或已有成员快速闭环无需再派。

这些落点不要求三个角色同时出现。最终两题验收除应用结果外，分别报告角色机会是否发生、是否发现/尝试、实际启动与模型、返回、父决定的变化、未触发和缺证；不把低分全部归咎于零调用，也不把一次成功咨询当作已证明的分数增益。
