## 问题与目标

讨论追问的不是如何让更多 Agent 并行，而是：主代理能力和注意力有限，怎样采用另一个可能出错的执行者的成果，而不付出接近亲自完成的复核成本。上下文交接成本是一层，采纳结论需要什么依据是另一层。

A1 指出三个极端都不解决问题：盲收会传播遗漏和错误；独立重做可能吃掉全部收益；再加一个相似模型的 verifier 只是递归转移信任，且错误可能相关。用户 U1 把方向进一步落到“父理解一个短查询，而不是读完全部原始数据”。收益机制因此包括**减少父必须承载的原始信息**，不只是降低执行价格、并行耗时或让返回容易审查。

A3 将目标推广为总成本和后果的折中：交接/整合、验证、误收损失以及误拒后的返工都算成本。少检查不天然省钱，多检查也不天然可靠。这里是定性决策模型，来源没有提供可直接估计这些变量的实验数据，不应做成必须填数的评分表。

## 因果机制与取舍

1. **把大问题变成更小的可判断对象。** 搜索大量源码后返回一段范围明确的结构查询，或对大量记录给出一个关系不变量查询，使父审查查询含义、输入范围和结果解释，而非重复全文调查。返回更长证据包可能提高可审查性，却仍增加 token/时间；它不自动实现这种压缩。
2. **可靠性来自命题与检查的对应关系。** “没有直接调用”可由正确范围内的 AST 查询支持；“没有任何动态依赖”不能由同一空结果推出。编译成功不能证明业务正确，哈希相同不能证明内容符合需求。工具名称不是证据等级。
3. **执行结果与执行者转述有区别。** A3 对前面查询思路再补一层：仅收到“运行过、结果为零”的文字仍是断言，须能取得与实际输入/环境对应的执行结果。它随后主张由独立控制面执行，是一种较强实现提案，不代表所有消费都必须重跑子任务或建立新控制面。
4. **可信条件不会消失。** 正确查询仍依赖范围、版本、环境和工具语义。作用对象改变后，旧结果未必继续有效；检查器复杂到接近原任务时，委派收益再次消失。
5. **没有便宜判定器时保留判断。** A3 明确承认产品品味、战略和部分设计没有通用客观 oracle；可用论证、反例、真实反馈和较小可逆承诺降低不确定性。增加模型观点不能制造客观真值，也不能因此禁止委派开放问题。

## 从来源整理出的工作方法树

这是一棵整理后的阅读导航，不是来源已批准的 SOP，也不要求每次按顺序走完。

```text
采用外部执行者的成果
├─ 判断收益：直接完成与交接、执行、消费、返工及后果比较
├─ 塑造工作：所需决定/效果 → 可返回候选或结论 → 足以采用它的观察
│  ├─ 可精确检查：短查询、固有约束、契约、确定性检查
│  ├─ 无唯一答案但有关系：不变量、差分、往返或守恒
│  ├─ 全量过贵：有适用假设的抽样和渐进证据
│  └─ 开放判断：论据、假设、反例、未知及真实反馈
├─ 完成局部工作：生成候选，利用具体失败信息修正
├─ 消费结果：理解小检查/论据与命题的关系，取得实际观察并限定范围
└─ 决定后续：采用、返修、保持未知；按影响与可逆性控制进一步承诺
```

这比把全部任务塑造成布尔检查更忠实：A3 自己给出无法精确判定的类别；同样，也比只要求“返回出处供父抽查”更完整，因为用户提出的关键是让父不必重新读原始证据。

## 执行细节与适用条件

### A2 十二类案例及实际边界

| 来源案例组 | 为什么可能便宜 | 不能因此推出什么 |
| --- | --- | --- |
| 文本/AST 存在性查询 | 明确模式和范围可压缩大量源码 | 空结果不覆盖别名、反射、生成代码或遗漏范围 |
| SQL 集合与不变量 | 布尔值/少量计数替代读取海量记录 | 必须处理 NULL、join 重复、历史/软删除、时间点；必要条件未必充分 |
| 编译/类型检查 | 语言与类型约束由现成工具判断 | 业务行为或外部契约正确 |
| Schema/接口结构验证 | 对结构化候选检查既有约束 | 约束本身完整表达需求 |
| 数据库约束/事务 | 错误可在写入路径被阻止，减少事后查错 | 所有产品规则都能或应被数据库表达 |
| 代码/输出差分 | 观察变化范围、兼容关系 | 文件范围正确就功能正确，或新旧一致即绝对正确 |
| 可执行测试 | 对给定判据执行通常比实现便宜 | 测试与实现共享误解时的绿色不等于需求成立 |
| 属性/不变量 | 少量关系覆盖多种具体输出 | 抽样性质自动证明全部输入 |
| 求解器/证明检查 | 某些结果存在比搜索更易检查的见证 | 任意开放任务都能低成本形式化 |
| 哈希/签名 | 检查一致性、来源或身份 | 产物质量与内容语义正确 |
| 文件/权限/部署状态 | 精确状态查询替代全文日志 | 服务启动就用户旅程成功 |
| 策略规则 | 已明确规则可重复检查 | 规则形成不需要产品/组织判断 |

原文的强/弱验证器分类是启发式说明。整理者复核：其精度最终取决于所声称命题和条件，不能把 grep 永久定为弱、测试永久定为强。原文代码是讨论示例，本次没有执行或验证其命令版本、参数、退出码、NULL 等具体语义，不可原样作为已验证操作规范发布。

### A3 推广的十节及可保留内容

A3 依次讨论：总成本根因；证据承载的委派；查询实际执行缺口；工作/验证/效果分离；五类判断手段；将模糊目标变成可观察问题；检查器自身约束；按风险调节投入；返回结构；三次责任迁移。对应应保留的操作含义如下：

- 精确检查、关系检查、概率证据、结构化论证、不可廉价验证判断是不同适用条件，不是所有任务必须升级遍历的五级阶梯。fuzzing、canary 等也不能不加假设就声称有明确错误概率界限。
- 先想什么观察能影响采用决定；候选可以由子代理生成，合适检查也可由它提出，但检查应回到需求/外部事实，而非只配合当前实现。
- 失败返回具体反例比只返回红灯更利于局部修复；父无需中转每次工具输出。
- 结果要对应实际候选、范围和环境；保留尚未支持的结论。不是强制每次填写 commit、数据库快照、时间区间等全部字段。
- 验证投入随错误后果、可逆性、可发现性、不确定性和成本变化；源文列出的静态检查到形式化证明顺序不能直接变成固定流水线。
- 主张由控制面填 results、每项效果经闸门、固定 certificate/coverage/effects 字段，是末条 assistant 的较强架构方案。可提取“自报与观察区分、影响范围受约束”，不恢复三层框架或通用 schema。

## 与当前 SVC 及四项已认可方向的差异

对照依据：[当前方法复审](svc-method-review.md)、[运行接缝审查](svc-runtime-seam-review.md)，及当前 `svc-task-packet/references/delegation.md`、调查/实施专项 delegation、verification 入口。这里只提出修订建议；四项方向已获用户认可，不等于原来源最后所有提案已获认可，更不等于本报告授权实施。

| 已认可方向 | 来源支持什么、没有证明什么 | 建议修正的设计 |
| --- | --- | --- |
| 1. 独立 `svc-delegation`，迁移而不重复，其他技能路由 | 讨论本质独立于 task packet，但没有讨论 skill 布局 | 保留已认可入口迁移。新入口先解释降低父执行/消费负担的机制与适用条件，不先铺角色或字段。验证细节仍路由 V&V，不再复制一套验证学说 |
| 2. 独立有用结果、局部反馈、集成边界，开放问题可委派 | 可生成便宜可检的结果是核心，但 A3 同时承认无便宜 oracle 的判断 | 增加“塑造可便宜消费/判断的工作”这一方法，不只是把任务切小。问子返回能让父避免哪段原始材料/重复劳动；没有判定器时返回论据、反例与未知，不强制把开放问题伪装为布尔题 |
| 3. 角色由反复出现的问题、方法/工具、可消费返回形成 | 来源否定身份、自信或投票等同正确；未提出具体角色设计或模型等级 | 保留当前角色内聚方案，其依据来自方法与运行审查，勿称原讨论直接证明。角色可通过擅长构造某种可消费结果形成，不只按工作阶段或工具名分工；不新增固定 verifier 角色 |
| 4. 输入含 owners/in-flight/共享前提，区分信息消费与产物验证 | 来源直接挑战父反复读取原始证据；在途所有权不是本来源内容 | 必须修正仅二分的消费树：信息结论也可能用 SQL/查询独立检查，产物质量也可能只能论证/观察。在“信息/产物”之外，加看结论可检性、实际观察来源及错误后果；按需复用或补证，不默认重做，也不只读报告便采纳 |

当前 SVC 已有成本比较、按任务能力而非固定模型排名、单写者、传场景前提、父负责整合和 V&V 判断；不必重写为“不可信 worker + verifier”架构。当前方案的新增重心应从泛泛要求更清楚的输入/结果，推进到**结果怎样减少父需要重新处理的信息，同时保留足够的采用依据**。这是本次来源最值得改变设计的发现，不能缩成附两条查询示例。

本来源也提醒两项保留：不要仅计算错误接受的损失而忽略过度拒绝/过度验证造成的返工；不要将“由可靠工具执行”误解成“任何工具输出都等于产品正确”。这些原则可由 delegation 简短说明，细节由现有 V&V 承担。

先修订 `svc-method-review.md` 的顶层机制与消费分支，使上述不对称和不同判断路径可见；再设计已获认可的新 delegation 入口、专项引用迁移和最少例子。例子至少应对照“SQL/结构查询压缩事实验证”与“开放方案返回反例/未知”，各说明什么足以采用、什么仍未证明，不规定新 schema。
