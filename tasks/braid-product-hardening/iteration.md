# 本轮迭代的目标与修复链
目标：让 Agent 按需求形成可靠判据、完成协作与交付，同时能迅速解释失败、token 消耗和时间去向。
实验用于判断这些行为是否改善，不以成功启动替代完整验收。

```text
可靠且可诊断的无人值守交付
├─ Braid：协作消息与可编辑记忆
│  ├─ 已完成：重放、冷恢复、Codex 收据及三类精简
│  └─ 已批准并实施：追加触发 reset、收件范围、关闭自然收尾；保持既有交付范围
├─ 工作方法：保留需求与验收依据
│  ├─ GitHub：实现偏离需求后，测试改成追随实现
│  ├─ Sheet：需求摘要丢前提，局部测试自造数据绕过默认状态
│  └─ 共享契约：已读裁决仍沿用旧实现，把不相容留到集成
├─ 工具使用：尽快取得可信反馈
│  ├─ 现有 PBB 的退出、日志、通知正确接线与使用
│  └─ 先判断环境/检查/应用错误；不由 Harness 编写应用脚本
├─ 实验设施：统一原始证据、token 与时间剖析
│  ├─ 恢复和监控验收：真实冷恢复平稳续进已验收，按用户授权取消官网运行
│  └─ 自包含 OTLP 接收/存储/查询，官网与 WSL 采用同一语义
└─ 冻结后实验：pi-braid-flash-team，WSL GitHub + Sheet
   ├─ GLM 根；Qwen/MiniMax 工作项 profile；原生子角色模型不变
   └─ 官方 API 自费 key；冻结后本地代理评分，不使用参赛额度
```

## 已观察的失分机制与方法修正
[GitHub 4/100](../github-score-diagnosis/results.md)：实际轨迹先按需求检查 link，失败后把判据改为实现的 menuitem；认证 API 通过不等于浏览器默认表单路径通过。
方案是将判据依据固定在需求和已确认契约；失败时先判断实现、检查或环境哪一项错误，不能仅为变绿修改预期；从交付默认入口验证完整路径。
不在 Harness 中写题目选择器、登录脚本或业务断言。

[Sheet 58/100](../sheet-score-diagnosis/findings.md)：根需求摘要省略 GIVEN 前提，共享基础只收到 A1 初始化要求；局部检查自行创建数据，绕过交付默认数据。
方案是让需求转交和验收设计保留行为前提/初始状态；明确哪些测试 setup 来自真实允许操作，哪些 setup 会掩盖尚未实现的需求。场景覆盖按实际判据，不按测试数量和标题推断。
上述失效行为均有独立复现和原生轨迹，但没有官方逐例失败明细，不能解释每一个官方失分或给收益百分比。

[共享契约与环境耗时方案](../experiment-infrastructure/time-cost-proposals.md) 是本轮共同方案输入。
Skill 采用不稳定不能直接等同未提供技能：冻结材料确实存在；需要改的是方法进入实际工作的位置与反馈，不再堆同义提醒。
新增方法内容先检查现有 SVC/design/verification/browser-checks 的权威归属，删除冲突和重复，再修改最小必要入口。

## 可观测性边界
采集由 Harness/Provider/工具/实验宿主负责，不要求 LLM 记录 token 或 trace，也不修改生成应用。
原始消息、工具执行、进程与状态事件保留；聚合视图能回到同一次调用和原始证据。
LLM token 来自 provider usage，费用区分实际账单和按冻结价格估算；缓存、推理、输入与输出分别保留来源。
时间区分模型请求/首 token/生成、工具进程、队列/资源等待、结果可用到消费、重建与恢复；并行时间不求和成总墙钟，未知区间保持未知。
独立采集不代替主办方隐藏评分记录；官方逐例错误不可取得的限制仍然存在。

可观测性具体职责、时间与 token 口径及验收见 [自包含诊断方案](../experiment-infrastructure/observability-design.md)。

上下文因果排查已完成，见 packet 与两份独立 cell。上述关键错误均早于对应成员首次 reset，GitHub 相邻催办未消费；Sheet 的 GIVEN 后续被实际读取却未纠偏。不支持这些错误直接由 Braid 重建/通知造成，也不证明 SVC 文本有缺陷。长上下文、排障负荷的增量影响仍未知；方法改进的效果仍待实际实验。
