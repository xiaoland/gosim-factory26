## 机制判断与优先候选

| 机制 | 本轮能确认的分类 | 不应作出的推断 |
|---|---|---|
| task-packet | 已读取、创建、后继沿用；部分更新与候选证据管理发生执行偏离 | 文档存在=责任闭合；或文档导致4分 |
| SVC methods | design入口实际读；workflow在运行期角色配置中内嵌；部分refs显式读取未发现；反例法有实际采用 | 没有read调用=没加载；加载=全部采用 |
| durable docs | 共享规则被实施者读取、提出修改、裁决和消费；局部速记仍与原文冲突 | 文档Skill正文没读=docs完全无效 |
| advisor | 局部问题复核有效；早期局部答复不能视为全设计认证；晚期存在401环境失败 | 增加调用数必然改善覆盖 |
| vision | 返回可见事实和缺失边界，主消费；不是完整视觉验收 | 缺图=模型失败；读图=页面已验 |
| explorer | 独立反例实际促成修改；范围受brief限制，主有选择地采纳 | 只读静态审查=独立运行通过 |
| executor | 有历史角色配置；当前审查窗口未发现实际原生调用 | 未调用=失效；Braid PR实施者=原生executor |
| Braid Issue/PR | 具体争议→裁决→实施→合并闭环有效；范围排除缺乏接手闭环 | 消息已投递=已消费；已消费=全部责任已落实 |
