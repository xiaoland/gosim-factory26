# 夜间实验独立判断

2026-10-02，北京时间。结论：**需要调整。先完成一条 GLM 根 baseline，再串行验证一个质量机制；不要把全面网关迁移、全部 DX 生命周期验收或四 variant 对照变成第一份评分的前置项目。**

本判断只读检查了本任务三份调查、baseline-roots packet、DX technical 合同、网关选路源码及 e2e 已有实际操作记录；没有请求模型、prepare、恢复、部署或运行设施测试。账户事实采用主线在 Helium 的实际观察，没有重复检查账户。Ponytail 仅用于质疑多余工作，不代替身份、预算或供应商兼容性约束。

## 先取得结果，再决定是否迁移

优先原 GLM-5.3 fresh baseline，原因是 GLM 完整交付仍是未回答的问题，且可为同根 reviewer 对照提供基线。它与原 Flash 使用相同新版 GitHub 需求 SHA `9480921cb3b7ffdc5f32cb76011ecc1d5bf9bfbf2cba38e3a092355ac88a54f8`。5 次与 1 次成功响应都只证明早期读技能/Issue；不能据此声称 GLM 已有显著应用进度，也不能把过去投入作为恢复优先级的决定理由。I13 Flash/Sheet 的 74 分不是本轮 GitHub 分数对照。

第一选择是按原冻结 Qwen route 恢复原 GLM attempt，而不是先把暂停现场换成统一 gateway。这个选择成立的判别检查是：在取得本轮开工授权后，由原执行入口完成一个真实生成 turn，确认原精确模型、工具调用、流式完成和当前 Qwen 请求受理，沿原 attempt 保存结果。它本身就是实验的第一步，不必另建一个模拟验收程序。原 controller/容器、attempt/incarnation 和恢复控制能力须先按已有公开回执核对。

普通 Qwen 的历史成功、K3/DeepSeek 免费剩余、74.67 元月账单均不能证明 GLM/Flash 今夜可持续使用：最新账户观察中裸 GLM 配额为“-”，Flash 为 0/0，余额未知。因此不能承诺这条路径不会再遇到余额或限流故障；其优势是已经装配且存在真实运行事实。如果首个实际 turn 明确遇到供应商阻塞，采用预先准备并获授权的 gateway 新冻结 GLM 候选，禁止在夜间临时开始第三套恢复方案。

新 gateway 候选的初始渠道优先 ARK Pro，精确使用后台已确认的 `/api/coding/v3` 及固定 wire ID；同模型备用可来自已核实的 Token Plan/普通 Qwen。不能继承 catalog 的 BigModel/Kimi 历史默认，也不加入 ARC。Flash/K3 不进入当前 Token Plan 链。DeepSeek `0731` 没有已证明同版本备用时保留单通道，不能把 ARK 不带日期的 Flash 或原厂旧别名当作同模型。

启动准备应采用一次短而明确的收敛窗口：建议从开工起 30 分钟内决定“原 GLM 已产生有效生成 turn”或“切到已通过实际入口验收的新 GLM 候选”。这是避免整夜准备的工程时间盒，不是声称必能在 30 分钟修完所有故障。若两个候选都不具备可运行证据，报告准确阻塞；不通过取消证据约束来声称已启动，也不把全部夜间时间继续投入跨代恢复。

主线最新 `df` 观察为 WorkSSD 仅余约 1.2 GiB，Mac Data 约 9.7 GiB。**这是比未知账户余额更具体的启动阻塞候选。** 开工前分别确认实际生成宿主、控制侧与应用回传/评分打包目的地，按现有 storage 合同和实际产物规模核算剩余生成、输出与复制峰值。域侧已有资产只消费原引用；gateway 新资产生产一次复用。不在 Mac 重建全套 runtime/prepared 副本，不为通过检查把历史 12 GiB 保护改成拍定的 1 GiB，也不删除现场或原始证据。若原远端执行可继续，但本地没有评分回传空间，须先选有真实容量的既有目的地，否则“已生成但不能评分”仍达不到今晚目标。

## 最多三个生成机会的串行树

一次恢复后执行模型的 baseline 计一个生成机会；新 run/attempt 的重启或从头生成再计一个。请求层已经冻结的同模型 fallback 不算新生成。每次应用发布后立即独立 self_funded 评分，`allow_competition_credit=false`；评分可以与下一次生成重叠，生成最多一个。评价输运失败留在同一评价闭环，不重跑生成。

| 当前结果 | 下一动作 | 上限与解释 |
| --- | --- | --- |
| 原 GLM 真实 turn 可用，随后生成完成 | 冻结应用、发起评分；同根 GLM 跑一个机制候选，默认 reviewer | 第二个生成机会；保留相同需求、根模型、成员策略及资源条件。 |
| 原 GLM 明确因供应商受阻 | 切入预先冻结的新 gateway GLM 候选，保全原现场；该候选成功后跑同根机制 | 分别消耗第二、第三个机会，不再补 Flash。若 gateway 不具备实际可用性，停止该分支。 |
| GLM root 在已冻结渠道均不可用，但 Flash 和共同成员渠道可用 | 使用预先冻结的 Flash 候选作为替代 baseline，再用剩余机会做同根机制 | 不假定换根能修复共同 DeepSeek/K3 通道故障；实际矩阵先冻结。它是替代路径，不构成 GLM 质量零分。 |
| GLM baseline 完成，且公开过程显示需求裁决或收口义务遗漏，或缺少可靠独立收口 | reviewer | 针对 I13 已观察的责任与需求裁决缺口；不把 Sheet 五项缺陷发给 GitHub Agent。没有浏览器证据本身也优先归这里，不足以证明工具缺陷。 |
| GLM baseline 完成；独立审阅责任和需求判据确实已执行，但公开证据显示连续浏览器操作受工具/会话反馈阻碍 | e2e，替代 reviewer | 同时记录其浏览器/runtime 变化；不并行再跑 reviewer。e2e 非 ARC AI 路由尚未验收时，采用已有手动 MCP 能力及已核实的外层模型，不临时追加多模态升级。 |

本轮自动分支只选择提前冻结的现有候选与操作。无需“评分好/差”的任意阈值，也不要求新建通用决策引擎。运行时分类不确定时采用默认 reviewer；不得把不确定的缺陷归因当作已证实的工具问题。若 reviewer/e2e 所需同根材料、当前 provider 或关键能力尚未准备好，不为凑满三次而临时扩建；可以将剩余机会用于已冻结的 Flash，或者停止并报告该缺口。

不设置用户未要求的 12 小时自动 kill。沿已有采集与十分钟监控消费保存摘要，连续约 30 分钟未见语义进展时触发一次定向诊断；这是检查门槛，不是 stale 终态或杀进程依据。根因明确且落在已授权恢复范围内，可完成一次针对性恢复；原因未知或同一故障反复，保全并通知，不无限重启。原有 wall/token/storage 安全预算仍须遵守，用户没有夜间硬截止不等于取消这些预算。

选择分支的人或监督者可以看到官方总分，用于报告与既定预算管理；本表不需要消费隐藏失败详情。仍在生成的 Agent、以及下一次独立生成的输入，只包含允许需求和预先冻结的通用机制。不能把官方失败清单翻译成“通用改进建议”再注入。根模型、供应商发生变化时标明比较条件，不以一次样本宣称机制因果已经证明。

## 最小真实验收与 fallback 合同

`scripts/hackathon_gateway.py:prepare_catalog()` 当前每个 alias 只保留一个 deployment。目录存在多家供应商并不形成 fallback；这是真实未实现接缝。采用已有 LiteLLM Router 能力是最小方向，但必须把选择、冻结、上游尝试记录和客户端流式边界接通。不要再造代理、统一运行数据库或新 manifest。

需要的三项真实反馈分别关闭不同不确定性：

1. 原暂停现场只用其冻结控制器/公开 observe-resume 合同确认原身份与真实 turn；不用今天新 CLI 擅自控制旧格式。对于新候选，用实际将执行的 native Pi 入口确认选定的 root/成员所用渠道能完成工具调用和完整流。没有参与今晚实验的 Responses、额外视觉候选和未选供应商不做验收。工具/流式请求能够一次覆盖时，不再额外要求每渠道一个纯文本请求。
2. 新 DX 运行须在真实候选中取得 ready、实际资源采样、entry 与应用发布事实；并沿现有独立 evaluate job 保存来源与官方回执。它们分别在自己的阶段确认。不能要求新 run 尚未启动时就已经拥有 Braid/native session ID，更不能把一份填满字段的人工 manifest 当作运行证明。完整 archive 或辅助 telemetry 尚未封口不自动阻止消费已成功发布的应用。
3. 若今晚宣称 fallback 已验收，必须取得实际首次通道失败、第二通道成功、同一客户端请求的 route-attempt 原件和客户端完整响应。没有自然发生的 429 时，不通过制造负载触发限流或另建故障探针；未发生的故障模式如实标为未实测，不能为了等待 429 耽误生成。独立确认两个实际候选可用，加上冻结 Router 的路径检查，只能支撑启用条件，不能冒充 429 实证。

对同一逻辑模型，预先冻结的供应商顺序可以在同一 attempt、同一 Braid/native session 内切换；provider route 是请求事实，不是新的 Agent 会话。冻结 config SHA、精确 wire model/API 形态、endpoint、凭据引用和费用许可，记录每次上游实际选择与原 HTTP 错误。原冻结 baseline 没有这条链时，临时增加供应商属于定义变化，应有新定义/run/attempt；但**新的执行 attempt 不自动要求丢弃可兼容的 native 历史**。是否恢复历史由既有 Harness checkpoint/兼容合同决定，不能把 provider 变化一概等同会话损坏，也不为保存十几 K 早期读取上下文而优先建设昂贵迁移路径。

今晚的最小请求政策：每次请求只有一个重试责任方，每个候选最多一次请求；短时 429 可按已冻结有界退避策略处理，套餐耗尽进入对应冷却；候选按顺序耗尽就返回原错。401/403/模型或参数错误不能在同一失效通道无限重试；是否允许切到已批准备用必须由已冻结错误政策明确，不自动扩大供应商集合。模型消费可能已经计费，不能把 fallback 次数当成免费请求。

流式边界是“是否已经向客户端交付任何有效内容/工具调用片段”，不是仅看 HTTP headers 或是否有工具真正执行。交付前明确失败可以按冻结顺序重试；交付后不把第二个模型输出拼接成同一成功响应，必须保留不完整响应并向 native 客户端显式报错。只有原生客户端已证明丢弃该未完成 assistant turn，且不会重复已提交工具效果时，才能在同一 session 完整重试该 turn；今晚未验证这一能力就不承诺自动修复半流。不能依赖 Responses continuation 的实现存在推断跨供应商历史语义等价。

无同版本候选时，明确停止该模型的自动 fallback；跨模型替代属于新实验条件，必须预先列入有限树并消耗新的生成机会。不得以自动降级绕过昂贵模型单 Braid session 保护、历史排除模型或不同能力边界。

## 对已有调查的必要修正

`recovery-boundary.md` 已确认公共定义与运行数据有明确分工，且没有找到 attempt 状态写回 definition 的路径；只能说 legacy variant 重复装配与历史恢复入口存在成本，不能据此诊断“variant 边界混合就是主要耗时根因”。今晚只使用一条明确入口，记录实际打包/启动/恢复阶段耗时；暂缓 variant 架构重写。

`results-evidence.md` 中“评分较好/较低”无需再补高分阈值；直接替换为上表的公开过程证据分支。“每条实验必须列出五类行为证据”也不适合新版 GitHub：那五类来自 Sheet 历史，不能成为本轮强制完成条件。完整评分、公开需求验收和机制是否实际采用分开报告即可。

需在开工材料明确的缺失事实只有：原 Qwen 路由当前是否真实受理、所选新渠道的 native 工具/流式兼容、既有旧控制器是否可以继续完成生成与评分派发、同根 reviewer/e2e 是否已经具备可消费材料。账户余额若能直接读到可辅助排序，但不是用历史账单推断的数值。其余未选供应商或完整生命周期故障矩阵可以留到实际需要时；第一份有效应用和评分闭环成立后，不追加一轮全面设施审计。
