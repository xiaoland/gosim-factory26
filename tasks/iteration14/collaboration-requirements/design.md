## Skill 的 What／Why 边界

用户认可 Skill 主体回答足以区分选择的 What／Why，暂缓 Hook。实现 `a31eb888` 以目的、概念差异、因果关系和成立条件组织两主文件及方法 references，现有中性例子解释判断分叉。固定阅读顺序、Git 定位命令、提交/push 教程和重复整理动作已移出主体；消费者可发现、可取得且适用于候选的材料条件仍保留，文档与 packet 方法仍指向 SVC 独立入口。

具体性由决定条件保持：接手安置责任，适用结果支持兑现；派生约定的发布没有改变原要求；真实入口的调用条件连接接口能力与用户结果；变化影响决定旧证据适用范围；有效局部成果可以先合并，整体仍需剩余承诺的依据。ARC 父层语义、跨枝操作、场景初态与图片事实仍各有判断依据，平台确切外部合同留在原 reference。

Hook 只可能帮助触达，生命周期并不等于语义决定时点。Ponytail 4.10.0 的生命周期 hook 和 Pi `before_agent_start` 会注入技能正文，与本项目独立文件规则冲突；当前不引入这种机制。今后是否重开此方向，应由具体触达失效与决定效果证据支持，而非读取次数。

## 消费入口的决定

四个 `run.py` 的 root prompt 保持现有本次需求、arc-bench 路径和交付约定。Pi 原生发现已提供名称、description 与路径，重复 frontmatter 的原建议已撤回，记录为 `60ba2e01`。

恢复换版通知提供材料变化事实、名称、实际路径与新身份，不重复 description 或内联正文。承担组织、接手、需求解释、采用或验收决定的人按当前问题取得适用新方法；恢复本身不使全体成员都必须立即复读两技能。文件更新、系统发现、通知送达和实际采用是不同事实。

## cleaner 与负责人

| 消费者 | 结果与边界 |
| --- | --- |
| cleaner | 整理当前 description 和讨论，呈现已明确采用的决定、未决义务和证据入口。缺证据或冲突仍保留，不产生新的正确/完成结论，也不改变责任。 |
| 实施或接手成员 | 依据已提供材料推进工作，判断接手是否包含完整义务，核实真实接口与调用，发布自身成果及文件。查询服务于具体未知，例行整理交 cleaner。 |
| 需求与验收责任人 | 裁决新行为、采用候选、判断结果范围和整体完成。原文、真实调用及完整消费者结果仍是成立依据。 |

cleaner 的一次 registry 请求没有工具，只取得触发前有效历史及稍后的完整维护快照，system 来自其 common 与职责文件。它不能独立读技能、核实文件发布、检查应用或判断真实结果；新快照证明对象较新，不证明主张正确。必要维护职责可在其独立 role 文件定义，方法技能仍保持独立文件，不能由 extension 读取正文后内联。

最小入口调整是取消 cleaner 两份成员指令中按开始/接续强制读技能的开场，使已有投影可直接消费，相关未知按判断取材。主线已提交 `b13f4290`，只改 fast/root 两份 instructions 首段及主 packet；本次只读核对了其源码。`MAIN_SKILLS`、SVC 文件发布/packet 责任、cleaner 一轮无工具能力与 core 保持。现有 cleaner 职责文件基本足够，无需增加工具或通用 Hook。
