# 固定批次的局部计划

Owner：feedback 主线的固定批次执行单元。状态：TBC，等待三个 ready Cell 的共同出口；没有启动生成或 bench。它是消费共同返回的一条线性 Plan，不是另一个 Cell 或共享 Phase。计划当前由主 Agent 持有，执行时再明确持有长进程与终态返回的子 Agent。

本执行单元 消费同一版本的 multi-agent 接入产物，比较四种组合在 ARC-Bench-Lite 的完整结果，并把失败和限制交还用户。它不负责边跑边换 harness、重复生成直到高分，或自动决定下一轮。

## 出口与依据

固定四个 variant × Keep/BookStack 八项独立生成/评测，逐项保留阶段、实际调用/协作、冻结应用、官方结果及证据。完整 variant 需 Keep32/BookStack34 全量评测齐备；缺题、skip、部署失败或中断不可伪称完整分数。所有预排项进入终态后汇总停止；系统性设施问题导致暂停时，给真实终态与未完成清单，不标 satisfied。

批次输入、模型调用范围、冻结/隔离、结果与失败定义沿用 [verification.md](verification.md)及 [experiment-design.md](experiment-design.md)，不因采用 Cell 重开已定验收。

## 局部计划

1. **01：接收并冻结实验输入。** 核对三个 ready Cell 的返回、源码/材料/模型映射、固定 runner 与实际用例身份。恢复已有在途项时先确认真实进程；历史 run 和原始调查路径不改写。
2. **02：运行固定八项批次。** WSL 初始两路生成、最多四路独立单-worker评测，记录内部 Braid/原生模型并发与限流；复用缓存、隔离工作区和浏览器。后台进程/子 Agent 终态返回，主 Agent 不频繁 polling；远端只有缺少事件接口时，后台采集从 180 秒起。

## 02 结果（2026-09-22）

八项均取得官方 ARC-Bench-Lite 评分，汇总与恢复边界见 [实验报告](../../reports/2026-09-22-multi-agent-lite.md)。总分最高为 pi-team 的 31/66；本轮包含 Braid revision 更新和两项确定性导出恢复，不能当作严格同源码的最终消融结论。按约定在取得八项评分后停止，下一轮方向由用户复核结果后决定。
3. **03：返回完整结果或明确残余。** 逐项终态短报，按通过率、失败层次、实际协作和证据完整性形成批次比较并停止。组合差异不作单因素归因，Agent 未使用某能力要如实说明，不能要求它为了证明 multi-agent 而强制拆题。

ready 出口未满足时，01 保持 TBC。普通应用低分继续预排清单；系统性配置/协议/隔离错误暂停队列并返回相应 owner，保留在途证据。已终态失败不自动重跑，不把官方失败详情回灌同次生成。下一轮实验由用户决定。
