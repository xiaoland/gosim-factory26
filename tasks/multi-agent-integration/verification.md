## 用什么证据回答什么问题

| 目标性质与场景 | 判定方法和观察位置 | 有意义的反例/失败结果 |
| --- | --- | --- |
| Factory 组合不泄漏进 Braid | 两个 Factory preset 引用同一 profile，用相同工作项输入核对 Braid 接收的普通 profile/运行绑定；改变另一个未使用 profile，已有 profile 修订不变。检查 Braid API/CLI/数据库不出现 preset/variant 语义字段。 | 整组摘要改变导致无关 Braid 会话失效，或 Braid 需要读取 Factory variant 文件，均失败。 |
| 配置按责任组合且可追溯 | 验证 preset 引用、角色/技能依赖均能显式解析；缺引用、重名、未知参数在启动前报错。核对实际加载的角色：仅 pi-verification 提供 reviewer，无 contract-reviewer；所有组保留共同 V&V。展开证据可追溯到原始 owner，不接受手改 effective-config。 | 静默深度 merge、重复模型权威、把 task/worker 混入 Agent 配置，或引用失败时降级为默认配置，均失败；共享模板意外向其它三组注入专职 reviewer 也失败。 |
| 工作项按明确 profile 执行 | 用本地 Braid CLI 创建两个不同 profile 的工作项；在实际 provider 请求捕获边界观察模型、reasoning、指令和能力摘要，而非仅看 config。默认值、显式选择和未知 ID 分别覆盖。 | 将 Pi 仍读旧单模型参数的行为作为回归反例；未知 ID 不留下半创建对象，两个 worker 不能抢走对方指派。 |
| 重新指派/上下文重建不丢工作、不并发旧写者 | 使用可阻塞的 provider 边界检查：保留未提交文件及讨论，指派到另一 profile，旧 writer 被拒绝；旧 session tree 停止后新会话才获得同工作树；重启中间状态可恢复。 | 中途断连或无法确认 child 停止时 blocked/unknown，不能伪装已切换；同 profile 无操作，材料摘要不同的 resume 拒绝。 |
| 原生主子能力真实生效 | 在 Pi 和 Codex app-server 各自的受控临时仓库中，主 Agent 调用预定 child，child 完成有可验证产物的局部任务，使用指定技能/工具，父 Agent读取结果。核对真实模型请求、角色、技能读取和 session 文件。 | 无模型替身仅证明调度不证明核心兼容；工具调用失败、技能缺失、child 证据缺失均明确失败，不算运行过该能力。 |
| 浏览器按物理会话隔离 | 使用选定浏览器工具，同一工作树两子会话访问受控小页面，分别写入不同 localStorage/cookie、截图后读取；各自多次调用保留自己的状态，另一会话看不到。 | 按 role/worktree 命名造成污染，或每条命令随机命名丢状态，都会失败。只看 browser 可执行文件存在不成立。 |
| 浏览器委派降低主上下文负担且保留局部反馈 | 受控任务由 operator 执行多步旅程并返回证据，executor 完成局部修复和浏览器自验；主会话能据短结果追问/决策，必要原始证据仍可取。 | 不能以消息字数少替代判断：缺失关键观察、每步都让主会话中转、或必须串行经过所有角色，都违背委派意图。简单一步直接操作不判失败。 |
| 父会话重建/取消覆盖 native children | 子代理在进行可观测工作时触发父 context reset 或 profile 切换；检查原生 stop/close 证据及文件写入终止，再检查新会话恢复。Pi 前台与后台两条路径均覆盖；Codex 检查其原生子线程。 | 仅父进程退出、child 仍写文件，不算结束。真实接口不能给出结束证据时标 unknown，不能启动竞争写者。 |
| 三个网关模型和 Codex 转换链兼容 | 用受控文本/小图和工具任务观察模型实际返回、wire reasoning 参数、工具 round trip 与 stream terminal；覆盖 Pi 上 K3/K2.7/GLM Flash、Codex 上 K3。与核心场景合并复用证据。 | 模型只接受请求却忽略已承诺能力、转换器丢工具/图像、流式未终态都不算通过；不因 HTTP 200 就放行。 |
| V&V 帮助选择可信证据，其余 Corpus 保持固定 | 用非 benchmark 的小需求，独立阅读者按候选 V&V 选择性质、Oracle、状态/输入和证据；核验需求破坏能失败、等价实现不误失败，验收/诊断不混用。核对实际安装与四组共同快照，并确认非 V&V 文件 hashes 未变。 | 仅增加术语/模板或要求每需求永久测试不算有效；冻结范围变化须显式处理，不借本批修改其它 Corpus。 |
| 诊断关联准确且可用 | 从一个真实或受控失败的 brief 出发，沿 profile/session/case 入口找到原始证据；与原生身份、模型调用、归档 hashes 和 ARC-bench report 交叉核对。 | 缺失证据必须可见；重复子会话不重复累计 usage；不把累计父用量与已含子用量再次相加。 |
| 八项批次不漏、不串、不暗中重跑 | 用现有阶段边界替身模拟 completed、应用失败、设施失败、进程失联及中断恢复；检查清单/run/输入/配置身份和实际阶段调用次数。 | 已终态失败不能恢复成新生成；unknown 必须确认原进程后再处置；系统性错误暂停排队项，普通低分继续清单。 |

局部检查优先扩展 Braid 现有本地对象/会话屏障测试、Factory 配置/原生归档/反馈测试；批次使用阶段替身只检验排队、身份、恢复等机制。真实兼容场景使用单独临时需求，不能偷看 Keep/BookStack 官方测试或借机修复历史应用。

reviewer 是否调用不作为通过门槛，也不新增一次付费调用来“走完角色”。若批次中实际使用，检查它提出的语义偏差或证据缺口是否有可核验依据；没有新增发现也如实记录。角色名称、另一份赞同意见或已有检查的转述不构成额外可信度。确定性检查与产品行为证据仍是所有组的共同基础；本批组合比较不能单独证明 reviewer 的因果贡献。

## 真实调用的明确范围

建议设计两个受控能力场景，分别使用 Pi 和 Codex app-server。实施前的独立预演先用隔离探针确认会改变方案的原生接口；接入实现后沿同一目标检查组合行为，能复用的证据不重复获取。Pi 场景先覆盖 K3 主代理及原生子代理，再让所需 K2.7 Code / GLM Flash profile 完成可观察局部任务；Codex 场景覆盖 K3 原生角色、浏览器与 Responses 转换。浏览器 skill 重点在 operator/executor 消费环境验明；不同 skills 在实际目标 profile 环境中验明，不必为每个配置字段单独启动一个模型实验。

场景目标是证明接口和隔离；不产出 ARC-bench 排名。其真实调用、安装和临时仓库写入随本方案获准后才执行。尽可能复用同一场景检验模型参数、图像、技能、子代理、浏览器与归档。失败后可以修复获准范围内设施并重验受影响场景，保留全部尝试及原因；不因偶发通过就隐藏先前失败，也不无限扩展探针。涉及模型替换、取消某能力或改变预期语义时重新复核。

不增加固定低 token/时长上限。明确的 API/协议错误立即结束相应探针；长时间无可解释进展由诊断证据判断，不能把任意 45 秒当作失败。模型配额和兼容参数未知以实际证据处理，不把它们伪装成已验证配置。

## Lite 固定批次

执行位置为 WSL 的固定开源 runner，报告名称为 Lite 两题本地完整实验。版本沿用 `1eb018367bedd618d3b9ced406ce07fb423d4956`，执行前重新校验干净 revision、requirements/assets hashes 与实际发现的用例身份。预期 Keep32、BookStack34；若清单不同，先查明身份变化，不自行改分母。

| Variant | Keep | BookStack |
| --- | --- | --- |
| pi-generalist | 一次独立生成，冻结后完整评测 | 同左 |
| pi-team | 一次独立生成，冻结后完整评测 | 同左 |
| codex-generalist | 一次独立生成，冻结后完整评测 | 同左 |
| pi-verification | 一次独立生成，冻结后完整评测 | 同左 |

批次前固定源码、共同 V&V 与其余冻结 SVC、skills、核心/扩展、模型映射和每项 config。共享固定工具与缓存，隔离各应用产出和运行状态；禁止跨 variant 分享应用、官方失败详情或从本批结果改进尚未运行组合。两项同时生成、最多四项冻结应用独立评测，各评测使用官方单 worker。

完整有效的单题结果要求官方用例执行齐全，失败用例是有效成绩，skip/中断/部署失败不能伪装成完整分数。完整 variant 才给总 passed/66 与两题宏平均。八项都进入终态才能结束既定批次汇总；若系统性设施问题暂停未启动项，则报告实际终态和未完成清单，不能称为完整比较。

终态摘要至少含：variant/task、输入和配置身份、生成/部署/评测/analysis 各阶段状态、通过/失败/缺失计数、实际主子模型/能力使用、会话证据入口、usage 完整性、墙钟时间及主要失败类别。逐项终态形成短简报；全部终态后比较四方向并停止，不自动补跑或选下一轮。

## 与实施顺序的关系

具体实施计划由 [三个 ready Cell](task-map.md) 持有，沿已认可方案开展独立 Agent 预演；预演关注运行绑定、重指派/子树收尾、技能消费和证据链等实际接缝。完成预演和约定的实现前提交，才修改产品源码。现有 `make test` 与相关 Braid/SVC 检查按影响范围执行，已通过且未受后续改动影响的检查不反复运行。任务包重组不重开已有验收复核。
