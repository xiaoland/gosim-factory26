## 时间归因

健康的模型生成与官方评测约占 3 小时量级，是业务本身的主要下界。其余约 5 小时主要来自：

1. **Qualification 后移**：真实 provider 生命周期、session identity、子树终止和 work-item 恢复在正式批次前一刻或批次中才验证。
2. **产物边界错误**：模型已经写出可用 application，provider/finalization/teardown 仍能把整个 generation 判废；恢复依赖人工找到 commit、导出和冻结。
3. **调度所有权分散**：主 Agent 同时读日志、判断根因、修改 Braid、恢复产物、续队列和写文档，昂贵注意力成为串行资源。
4. **观测信噪比不足**：已有大量 trace，但缺少阶段耗时、队列原因、artifact readiness 和单一 failure class；三分钟 polling 只减少频率，没有消除语义扫描。
5. **实验矩阵过早放大**：基础设施尚未证明稳定就预排八项；失败时又滚动 revision，最终结果可评分但不是干净对照。

优化不应继续增加提醒和规则。应改变三个可执行边界：正式评分前 qualification 并冻结；以 application commit 作为恢复检查点；由 controller 和低成本子 Agent 隔离调度及日志噪声。按健康段和最长正常生成估算，四路可用时完整八项约 2.5–3.5h；若每轮只比较 incumbent 与一个 challenger 的两个应用，则约 1.5–2.5h。
