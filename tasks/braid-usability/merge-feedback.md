## 机制与实现边界

第一条机制是“预先声明后置结果”：局部 API 验收被推广成整体完成，并将依赖 merge 成功的关单动作无条件接在 merge 后面。
后续已知反证没有回写到 Issue 状态和关闭理由，错误事实继续留在共享协作记录中。
Pi 按最后命令状态返回 isError=false 符合该 shell 执行结果；目前没有证据要求修改 Pi 协议、扫描所有 shell 文本或全局强制 set -e。

第二条机制是将协作阻塞变成单人目录清理。
Agent 已知道修改来自他人，但尚未确认对方活动与集成约定，就自行决定以自己的已验收分支为基准并提交对方工作区。
同名 assignee 会放大困惑，但不能单独解释这里已明确知道“另一个会话”之后的操作。

用户进一步定位：Braid 对 GitHub 协作体验的还原缺少 Git server 所承担的共同仓库边界，导致 PR 合并实现混入 Agent worktree 操作。
当前 `objects.rs::merge` 硬编码取得 Issue #1 的工作区并要求其干净；`apply_merge` 推进目标 ref 后还检查并 reset 该工作区。
因此分支的合并错误地依赖一位 Agent 的暂存区和未提交文件，并附带改变其工作区的副作用。
共同仓库保存已发布分支和提交，PR 的源/目标引用属于该仓库；各 Agent 的本地仓库与工作区保存自己的编辑、暂存和本地提交。
PR 合并推进共同仓库的目标分支，Agent 自主取得并整合新的分支状态。
这个产品边界解释了为何合并不应要求另一 Agent 的工作区干净，也不应替它 reset。
现有 merge 已基于两个 commit 构造合并对象，可以复用该部分，修正其所操作的仓库与后续副作用。
技术方案不能只删除 dirty 检查和 reset：若 Agent 的符号 HEAD 仍直接指向被推进的 ref，其 HEAD 会移动而 index/文件仍旧，依然影响它看到的本地变化。
同一 Git 仓库下不同 worktree 仍共享普通分支 refs；仅分开目录不足以自动获得客户端与共同仓库的边界。

## 实现候选与待核实点

主 Agent 建议优先核实本地 bare repository 作为共同 origin、各 Agent 使用独立 clone 的最小方案。
原生 Git 的本地路径 remote 已能提供 push/fetch，不需要为此部署 HTTP/SSH 服务或引入托管平台。
可使用已有 worktree 能力组织各客户端内部的工作目录，但不能让它们直接共享共同 origin 的可变分支命名空间。
根 Issue Agent 同样是客户端；其统筹职责不要求持有服务器侧工作区。

技术设计需核实工作项/PR 分支初始化、发布提交与 ready 的关系、合并目标、客户端取得更新、恢复及最终产物读取。
本地 commit 与发布给协作者的 branch head 分开后，PR 必须引用实际发布的版本，不能把客户端未发布的提交或未提交文件解释为共享成果。
现有根 Issue prompt 含“禁止 push”，需随此方案澄清对本次共同 origin 的正常发布操作，避免工具与指令互相矛盾。
上述为待复核实现候选，尚未进行源码修改或实验。

## 待复核修正方向

1. 补齐共同 Git 仓库与 Agent 本地开发环境的边界，并据此修正 PR 合并：依据共同仓库中的源/目标提交计算合并、推进目标分支、记录实际 PR 状态。Agent 自主发布提交和取得更新；合并不操作其 index 或工作文件。具体仓库接线采用经核实的最小方案，不扩展协作决策或调度。
2. Braid 操作反馈明确说明操作是否发生、当前 PR 状态、源和目标提交；涉及工作区时标明分配给哪个工作项和具体成员，不把配置名当负责人，不暴露 UUID。issue close 仍是 Agent 的语义决定，不解析关闭理由或机械要求所有关联 PR merged。
3. SVC 的通用反馈方法覆盖依赖动作和共享记录：在观察前置操作结果后再执行依赖它的动作、作出完成声明；反证出现时先纠正受影响的计划、状态和报告，再推进恢复。将协作对象视为可独立变化的环境，涉及同事的进行中成果先通过讨论确认交接，再在明确范围内整合。内容保持通用，不写 ARC 或 Braid 特定关单规则。

当前 SVC 已有“工具成功不等于产品成功”和结果与实际产物绑定的原则；这次发现指向如何让操作依赖、状态修正和协作接续具体落地，不能仅增加一句“合并失败不要关单”。
共享基础框架的分工仍由 Agent 决定，Braid 不固定任务图或指定唯一集成人；本方案也不增加沙箱或接管原生子代理生命周期。

后续真实验收要观察实际合并结果、协作声明、集成提交及最终应用验收的对应关系。
单次运行不能分离模型能力、提示词采用与合并实现修正的贡献；当前证据足够支持以上两条行为机制和实现边界问题，不足以断言换模型即可解决。
