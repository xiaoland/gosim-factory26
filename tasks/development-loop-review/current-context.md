# Factory26 对照依据

本页只整理当前可见会话及仓库文件中的事实，供比较两段指定历史时使用，不预先给它们下结论，也不另设一套工作规范。

用户已建立的协作约定是：先诊断并提供因果清晰的方案供复核，设计验收，规划实施并用独立 Agent 预演，实现前提交，实施后自行完成可执行的验收。每次实验成功或失败都先汇报，再决定下一轮。原文应用见 [既有工作方法](../multi-agent/working-methods.md) 和根 [AGENTS.md](../../AGENTS.md)。

用户强调开发设施对行为的影响：昂贵主模型的注意力有限，信噪比应结合任务语义优化，可交由便宜模型提炼；确定性采集、长等待和终态通知由程序/运行 Agent 承担，不以高频主模型 polling 获取进展。任务包可以按需要自动创建，承载发现、方案、结果、计划和可复用的实验材料，结构围绕工作自然展开。

当前可观察偏差有三项。第一，agent-profile 调查已得到决定配方所需的主要事实，却继续核对原生配置细节，直至用户指出“半天了”仍没有具体 preset；这里没有足够计时证据，不能量化耗时比例。第二，原有 AGENTS.md 和 multi-agent packet 已写入协作顺序，但新的任务包直到较晚才形成可恢复的状态与提案；说明“已有规则”不等于实际工作在消费它。第三，AGENTS.local.md 仅有模板文字，没有具体指导；本轮已删除，不能把文件存在或文档数量当作外部记忆有效。

两份 preset 提案现已记录，尚未批准实现。本次历史分析要检验的假设是：是否需要让调查成果更早进入可复核方案，让任务包成为下一次工作直接读取和更新的入口，以及让分派真正移走材料解释负担。这些是假设；指定历史中的正反案例将决定保留或修正，不直接转成更多提醒或固定表格。
